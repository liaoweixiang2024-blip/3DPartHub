## 更新标题

3DPartHub v4.6.2 - 上传分类记忆修复 + 转换失败重传误跳过修复 + 转换内存不足报错增强

## 标签描述

v4.6.2 fixes three upload and conversion issues. First, the upload modal never actually remembered the last selected category: the stored-id validation only accepted UUID-shaped values, while this site's category IDs are Chinese names (the seed script uses names as IDs), so the memory silently never worked — validation now accepts any sane id and still falls back to empty if the category has been deleted. Second, re-uploading a model after a failed conversion was wrongly skipped as "duplicate": the batch dedup check counted leftover FAILED records from the earlier crash; it now only treats COMPLETED models (same name + same file, same category) as duplicates, so failed leftovers no longer block re-uploads. Third, conversions that exhaust memory now fail with a clear diagnosis instead of a bare "child exited with SIGABRT": conversion child processes get an explicit --max-old-space-size (75% of the container cgroup quota), so JS-heap exhaustion raises a readable "JavaScript heap out of memory" error, and SIGABRT/SIGSEGV/SIGKILL exits now report the source file size and the container memory quota with actionable advice (raise API_MEMORY_LIMIT, or split files over 200MB); the manual reconvert path gets the same heap limit and signal-aware errors. Recommended for large/complex parts: raise API_MEMORY_LIMIT to 3G in .env. No database migration.

## 更新描述

本次为 **上传/转换三修复** 版本，无数据库迁移。

**① 修复：上传弹窗从未记住上次选择的分类**

- 根因：本地存储的分类 id 校验只认 uuid 格式，而站点分类 id 是中文名（种子库直接用分类名当 id），记忆功能从未生效过（与 PDF 无关）
- 修复后中文名 / uuid 分类 id 均可正常记忆；分类被删除后仍自动回退为空

**② 修复：转换失败后重新上传被误判「重复跳过」**

- 批量上传的去重检查把上次转换失败（如内存不足崩溃）残留的失败记录也当成「已存在」，删除后重传同名文件仍被跳过
- 现在只有**转换成功**的同名同内容模型才算重复，失败残留不再拦截重新上传

**③ 增强：转换内存不足时报错可诊断 + 子进程堆上限**

- 转换子进程按容器内存配额的 75% 显式设置 `--max-old-space-size`：JS 堆内存不足时抛出可读的「JavaScript heap out of memory」错误，而不是一句干巴巴的 SIGABRT
- SIGABRT / SIGSEGV / SIGKILL 退出时，报错附带**源文件大小 + 容器内存配额**，并区分提示「调大 API_MEMORY_LIMIT」还是「超过 200MB 请拆分上传」
- 手动重转（标准引擎）同样接入堆上限与信号诊断
- 服务器建议：仍有超大/复杂模型转换失败时，把 `.env` 中 `API_MEMORY_LIMIT` 提到 3G（默认堆上限随配额提升到 2.25G）
