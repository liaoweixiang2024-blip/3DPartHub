# v5.9.6

发布日期：2026-10-20

## 更新标题

3DPartHub v5.9.6 - 修复「修复转换后换回标准转换预览不更新」缓存 bug + 审计日志强化（记录 IP/UA、登录显示具体用户、模型下载纳入审计）

## 更新描述

本版修复两个后台使用中暴露的问题：① 编辑弹窗「标准转换」在「修复转换」之后执行时，DB 里的预览 URL 版本号不换新，浏览器按同 URL 吃缓存导致预览一直显示修复转换（gmsh）的模型，且文件大小/零件树元数据停留旧值；② 审计日志此前不记录客户端 IP 与 User-Agent、登录日志因请求发生时未认证而全部显示「系统」、模型下载令牌被排除在审计之外——普通用户「登录+浏览+下载」的日常行为在日志页几乎不可见。

## 变更清单

### 1. 标准转换丢弃子进程产物元数据的 bug（核心修复）

- 根因：手动重转走 fork 子进程（避免转换冻住全站），子进程只写盘不写 DB，产物元数据（新 `?v=` 版本号 / gltfSize / previewMeta）经 IPC 发回父进程——父进程只接了缩略图，把 `result` 整个丢弃，再「重读 DB」读回的全是转换前旧值
- 后果链：`gltf_url` 的 `?v=` 不换新 → 浏览器缓存一直显示上一版模型（典型场景：gmsh 修复效果不理想换回标准转换，预览死活不变）；`gltf_size` 与磁盘不符；`preview_meta`（零件树）停留旧引擎产物
- 修复：IPC `result` 接住并落库（gltfUrl/gltfSize/previewMeta 三字段），runner 侧明确只回传落库所需小字段
- 修复转换（gmsh）链路与上传转换链路复核无此问题（前者自打版本号，后者 worker 自写 DB）
- 端到端实测：gmsh 修复后接标准转换，DB 三字段全部刷新（新 `?v=`、size 与磁盘精确一致、零件树 11 个真实零件名恢复）

### 2. 审计日志强化

- **记录客户端 IP 与 User-Agent**：所有新审计日志的 details 增加 `ip`（trust proxy 已配置，生产取真实客户端 IP）与 `ua`（截断 180 字符）；登录成功/失败的安全审计可定位来源
- **登录日志显示具体用户**：登录请求发生时用户尚未认证，审计行 user_id 为空、只记了邮箱——审计 API 现按 `details.body.email` 反查用户名，**全部历史登录日志（本机 1421 条）立即显示具体用户**；查无此人的（如撞密码失败）前端兜底直接显示尝试的邮箱
- **模型下载纳入审计**：`/api/downloads/model-token` 此前在审计跳过名单里，现在记录为 `download` 动作并带模型 ID（resourceId + details.body.modelId）；配合图纸下载令牌，谁下载了什么模型在日志页可查
- 前端日志页：操作者列兜底链加邮箱；详情面板新增 IP / User-Agent / 模型 ID 三行；五语言（zh/en/ja/ko/de）同步

## 审计确认

- 无数据库 schema 变更、无迁移
- 审计 API 仍为 ADMIN-only 可见；IP/UA 仅入审计日志（管理后台可见），不进入任何公开接口
- autoAudit 仍只记录变更类请求（POST/PUT/PATCH/DELETE），GET 浏览行为不记录（与既有设计一致）
