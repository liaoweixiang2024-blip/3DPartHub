## 更新标题

3DPartHub v3.8.1 - 修复分享链接 PDF 图纸 404

## 标签描述

3DPartHub v3.8.1 fixes the PDF drawing 404 on model share pages. The share info API previously returned the raw static path `/static/drawings/<id>.pdf`, but the drawings directory is intentionally blocked from public static access — so every drawing link on a share page returned 404. A new endpoint `GET /api/shares/:token/drawing` now streams the PDF inline with the same validations as the share download endpoint (link exists, not expired, allowDrawing enabled, share password verified via share_access_token), and the share info API returns this endpoint path instead of the static path. The share page passes the share access token for password-protected shares. No database migration; behavior of the download endpoint is unchanged.

## 更新描述

本次修复**分享链接页 PDF 图纸点击 404** 的问题，无数据库迁移。

- **[修复] 分享页「PDF 图纸」点击 404**
  - 原因：分享信息接口直接下发了图纸的静态路径 `/static/drawings/<id>.pdf`，但该目录出于安全考虑不对公网开放（图纸必须走带权限校验的接口），导致分享页图纸链接必然 404。
  - 修复：新增 `GET /api/shares/:token/drawing` 图纸查看接口，与分享下载接口同一套校验（链接存在、未过期、分享开启「允许查看图纸」、有密码时需先验证密码），校验通过后内联返回 PDF。
  - 分享页图纸入口自动适配新接口；带密码的分享验证密码后即可查看图纸。
  - 「允许查看图纸」开关关闭的分享：入口不显示，直接访问接口返回 403，行为与下载开关一致。

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**无数据库迁移**，直接更新镜像即可：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.8.1 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v3.8.1
```

升级后注意：

- 分享链接页的「PDF 图纸」恢复可打开（此前一律 404）；带密码的分享先验证密码即可查看。
- 分享的下载行为、次数限额均不受影响。

默认跟随 latest 的部署由 Watchtower 自动更新。
