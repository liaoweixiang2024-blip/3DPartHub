# v5.3.5

## 更新标题

3DPartHub v5.3.5 - 备份下载链路自检（下载前自动探测代理/CDN 是否支持断点续传，不支持时明确提示）+ 全量恢复缩略图统计口径修复（.jpg 漏计导致报「2 张」实际 6670 张）

## 标签描述

v5.3.5 ships two backup/download hardening changes. (1) Download-link health check: before a backup archive download starts, the client sends a 1-byte Range probe and checks for HTTP 206. Reverse proxies / CDNs that strip the Range header (e.g. BT-panel's global `proxy_cache`, which rewrites ranged requests into full-origin fetches) force browsers into whole-file restarts after any interruption - the "7GB backup downloads twice" incident diagnosed today. When the probe gets 200 instead of 206, a toast now tells the admin the link cannot resume, so the first person to download after any proxy change knows immediately. The probe reads only the status code (measured 14-18ms) and aborts the stream without receiving the body; probe failures never block the download. (2) Restore statistics fix: thumbnail counting after full restore only matched `.png` while production thumbnails are mostly `.jpg`, reporting "2 thumbnails" when 6670 files were restored intact - now aligned with the backup-side `.png + .jpg` filter. No database migrations.

## 改动一：备份下载链路自检

- **背景**：生产环境「点下载备份，第一遍进度走完又从头重下」。完整排查结论：源站 API 与 docker nginx 对 Range 断点续传的支持完全正常（206/416 实测全对），真凶是代理服务器宝塔面板在 nginx 全局开启的 `proxy_cache`——它会把带 Range 的请求剥掉 Range 头回源拉全量。Chrome 并行下载分段全部拿到 200 全量，分段计划作废后自动整单重下（详见本轮排查记录）
- **代理侧已修**：站点配置加 `proxy_cache off;` 后外部实测 206/416/中段续传全绿。本版本把「发现能力」做进产品：以后换任何代理，第一个下载备份的人立刻知道链路是否健康

| 文件               | 改动                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| browserDownload.ts | 新增 `probeRangeDownloadSupport()`：发只要 1 字节的 Range 请求，看状态码（206=支持），拿到即 abort 断流不收文件内容 |
| api/settings.ts    | `downloadBackup` 下载前串行探测（只多一个请求的 RTT），结果返回给 UI；探测失败（网络错误）静默跳过不阻塞下载        |
| SettingsPage.tsx   | 探测到不支持续传时提示：「当前网络链路不支持断点续传：下载若中断将从头上重新下载，建议网络稳定时下载」              |

- 实测：正常链路 14ms 判定 206 不打扰；坏代理场景 18ms 判定 200 并立即断流（GB 级流不进浏览器）

## 改动二：全量恢复缩略图统计口径

- 全量恢复后日志/结果报「2 张缩略图」而实际恢复了 6670 张（6668 jpg + 2 png）——文件本体无损，纯统计错
- 原因：恢复侧只数 `.png`，备份侧数 `.png + .jpg`，口径不一致；现对齐为同口径
