## 更新标题

3DPartHub v3.4.3 - 恢复体验改进（一键停止 + 实时进度 + 读清单优化）

## 标签描述

3DPartHub v3.4.3 patch release focused on backup restore UX: a one-click "stop restore" button that safely aborts an in-progress restore before the database schema reset (and refuses to cancel during the DB reset to avoid leaving a corrupted database), live archive-scan progress ("已扫描 N 个条目") so large restores no longer look frozen, clearer manifest-read messaging, and removal of a redundant manifest archive pass to speed up restores.

## 更新描述

- 恢复备份新增「停止恢复」按钮：在读清单 / 扫描 / 解压阶段（数据库 schema 重置之前）可一键安全取消——后台终止整个 worker 进程组（tar / pg_dump）、清理临时目录、释放任务锁，不会修改任何现有数据；一旦进入数据库恢复阶段（已重置 schema），按钮自动禁用，避免中断后留下不完整数据库。
- 恢复进度细化：扫描备份归档时实时显示「正在扫描备份归档... 已扫描 N 个条目，用时 Xs」，大备份不再像卡在某个百分比不动。
- 读清单阶段的进度提示改为「正在读取备份清单（大备份可能需要数分钟，请耐心等待）...」，不再停留在任务创建时的「正在解压备份文件... 0%」让人误以为卡住。
- 去掉恢复时第二遍冗余的清单 tar 读取（透传第一遍已读的清单），大备份每遍省数分钟。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## Docker Images

API image title: `3dparthub-api:v3.4.3`

API image: `ghcr.io/liaoweixiang2024-blip/3dparthub-api:v3.4.3`

API image description: Express/Prisma API service. v3.4.3 adds a restore cancel endpoint (cancelRestoreJob) that SIGKILLs the restore worker process group before the DB schema reset and refuses once the reset has begun; streams live archive-scan entry counts into the job progress; shows an honest manifest-read message; and reuses the already-read manifest to drop a redundant archive pass. Includes the v3.4.2 20-minute manifest-read timeout, all prior backup/restore/import hardening, secure temporary STEP previews, protected downloads, localized update flows, Redis/storage diagnostics, audit logs, queues, and production safety tooling.

Web image title: `3dparthub-web:v3.4.3`

Web image: `ghcr.io/liaoweixiang2024-blip/3dparthub-web:v3.4.3`

Web image description: React/Vite frontend. v3.4.3 adds a "stop restore" button to the restore progress card with a safety gate (enabled before DB reset, disabled during DB restore with an explanatory tooltip), surfaces the live archive-scan progress from the API, and treats a user-cancelled restore as a clean stop instead of an error. Includes localized legal/error/download flows, temporary STEP viewer, product gallery, selection sharing, inquiry/ticket workflows, admin pages, and responsive themes.
