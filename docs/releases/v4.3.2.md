## 更新标题

3DPartHub v4.3.2 - 修复生产环境备份文件下载 404「未发现文件」

## 标签描述

3DPartHub v4.3.2 fixes backup archive downloads failing in production with Chrome's "失败 - 未发现文件" (file not found) error. Root cause: backup downloads use nginx X-Accel-Redirect acceleration — the API validates the one-time download token, then hands the file off to nginx via the internal /\_protected_static/ location which aliases /app/static/. The host directory ./server/static/backups was bind-mounted into the api container only; the web (nginx) container mounted just the static-data named volume, so nginx looked for the archive inside the named volume's own (empty) backups directory and returned 404 while the API saw the file fine. The fix adds the same read-only bind mount to the web service, so both containers resolve /app/static/backups to the identical host directory. Downloads then stream through nginx sendfile as designed. One-line docker-compose change, no code or DB changes. After upgrading, recreate the web container (docker-compose up -d --force-recreate web is sufficient) and retry the download button on any backup record.

## 更新描述

本次为**修复更新**，仅改 `docker-compose.yml` 一行挂载，无代码改动、无数据库迁移。

**修复：生产环境备份文件无法下载（404 未发现文件）**

- 症状：网页端备份列表点「下载」，浏览器提示「失败 - 未发现文件」（Chrome）或「无法从网站上提取文件」（Edge）
- 原因：备份下载走 nginx 加速通道——API 校验一次性令牌后把文件交给 nginx 发送，但备份目录 `./server/static/backups` **只挂载进了 api 容器，没挂进 web(nginx) 容器**：API 看得到文件、nginx 看不到，于是 404
- 修复：给 web 容器补挂同一个只读 bind mount（`./server/static/backups:/app/static/backups:ro`），两端指向同一宿主机目录
- 本地开发（不经 nginx 加速）不受此 bug 影响，仅生产环境触发

**建议升级后验证**：后台管理 → 系统设置 → 运维维护 → 数据备份 → 点任意备份记录的「下载」，浏览器应正常下载 .tar.gz 文件。

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次改动在 **docker-compose.yml**（不在镜像里），**必须更新服务器上的 compose 文件**才能生效：

```bash
cd /opt/3dparthub
git pull                            # 拉取最新 docker-compose.yml（v4.3.2）
docker-compose pull                 # 拉取 v4.3.2 api / web 镜像
docker-compose up -d --force-recreate   # 重建容器（应用新挂载，绝不用 down -v）

# 验证 web 容器内能看到备份文件（应列出 backup_*.tar.gz）：
docker-compose exec web ls /app/static/backups/
# 然后网页端：设置 → 数据备份 → 点「下载」验证
```

> 若服务器上的 docker-compose.yml 有本地改动不便 git pull，可手动在 `web:` 服务的 `volumes:` 段加一行：
> `- ./server/static/backups:/app/static/backups:ro`
> 再执行 `docker-compose up -d --force-recreate web`。

默认跟随 latest 的部署由 Watchtower 自动更新（但 compose 挂载改动仍需手动执行上述命令）。
