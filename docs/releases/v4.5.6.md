## 更新标题

3DPartHub v4.5.6 - 下载文件名还原 / 回收站模型详情不可访问 / gmsh 按钮安装指引

## 标签描述

v4.5.6 ships three fixes: download filenames now always equal the original uploaded filename, soft-deleted (recycle-bin) models are no longer reachable from their detail URLs, and the gmsh repair button got a proper disabled state with a copyable install guide. Downloads: the "category prefix" stripping logic misidentified pipe-fraction names (SLF-2寸x3_4 = 3/4 inch, where 寸 sits mid-model-number) as "category_part" patterns and truncated downloads to "4.step" — 100+ library files were affected; the download path now returns the original filename verbatim (illegal-character sanitization + lowercase extension only), while the stripping logic survives solely for batch-upload content fingerprints (with fraction protections). Recycle bin: models with DELETED status kept serving full detail data to anyone with the link, on both the DB and metadata paths; non-admins now get 404 while admins retain visibility for recycle-bin preview before restore/purge. gmsh button: moved inline next to the standard-engine button, disabled (grey) when gmsh is missing with a red exclamation badge that opens an install dialog — apt install command, compose mount config, and restart command are all one-click copyable.

## 更新描述

本次为 **三项修复** 版本，无数据库迁移。

**① 下载文件名 = 上传的原始文件名**

此前下载逻辑会按「分类前缀\_零件名」规则剥离下划线前的部分，但管径分数命名（如 `SLF-2寸x3_4`，即 3/4 寸——「寸」字出现在型号中间）被误判为分类前缀，下载下来的文件名被截成 `4.step`，全库 100+ 个此类文件全部受影响。现在下载文件名**原样使用上传时的原始文件名**（仅清理文件系统非法字符、统一小写扩展名）——所见即所得。分类前缀剥离逻辑仅保留在批量上传的防重复上传指纹中，并补了分数命名保护（`竹节管主体-POM-1_4`、`双向止回式波纹管吸油装置_1_2` 等不再误判）。

**② 回收站中的模型详情页不再可访问**

删除模型（进入回收站）后，详情页链接仍对任何人正常打开并返回完整数据。现在软删除（DELETED 状态）的模型对非管理员一律返回 404「模型已删除」；管理员仍可访问，便于在回收站里预览确认后再恢复或彻底删除。数据库与元数据两条查询路径一致处理。

**③ gmsh 修复按钮重设计（编辑弹窗）**

- 「修复预览（gmsh）」移到与「重新生成（标准引擎）」同一行
- 服务器未安装 gmsh 时按钮灰置不可点，旁边出现红色感叹号
- 点感叹号弹出安装指引：`apt update && apt install -y gmsh`、docker-compose 挂载配置、容器重启命令——三段命令均可一键复制（含 CentOS 的 yum/dnf 提示）
