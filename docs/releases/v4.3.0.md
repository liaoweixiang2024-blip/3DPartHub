## 更新标题

3DPartHub v4.3.0 - 新功能：模块备份扩展（用户/工单/询价/审计日志）+ 备份数据安全五项加固

## 标签描述

3DPartHub v4.3.0 extends module backup with four new scopes — users, tickets, inquiries, and audit logs — so each can be backed up and restored independently (backup dropdown now offers 9 types). The users module restores by MERGE, never truncating: match by email-then-username, existing users get profile/permission fields refreshed while keeping their current password/avatar/login state, and new users are inserted with their original backup id so cross-module foreign keys still resolve. Safeguards around email/username collisions: an occupied field keeps its current value (logged), and a backup user whose keys are all taken is skipped with a log entry instead of failing the whole restore. Tickets/inquiries/audit use the standard clean-rebuild pattern, with ticket and inquiry attachments now included in the backup archives. Five data-safety hardening fixes across the module-restore chain: restore cancel is now blocked once the destructive phase starts (prevents half-swapped file directories), pre-restore safety snapshots are persisted with an in-progress marker so hard-crashed restores (power loss/OOM) get a one-click rollback entry on next boot, the cancel path cleans up its marker (prevents a stale marker from later triggering a wrongful rollback), backup retention policy now groups by scope with full backups exempt (small frequent module backups can no longer evict the only full backup, same rule for mirror directory), and the import confirmation dialog copy accurately distinguishes full vs module restore scope. Backup stats overview gains cards and counts for the four new modules. Decimal money fields (inquiry totals, item prices) round-trip losslessly. No DB migration required.

## 更新描述

本次为**功能更新**，无数据库迁移，升级即用。

**新功能：模块备份扩展——恢复哪个就导入哪个**

- 新增 4 种模块备份：**用户 / 工单 / 询价 / 审计日志**（此前只存在于整站备份，想单独恢复只能全量覆盖）
- 备份范围下拉现在共 9 个选项；备份列表/恢复确认弹窗按类型显示专属文案
- **工单、询价附件文件**（ticket-attachments / inquiry-attachments）随模块备份打包，跨服务器迁移附件不再 404
- 备份范围概览新增 4 张统计卡片（用户数、工单数+消息数、询价数+明细数、审计条数）

**用户模块 = 合并恢复（绝不清空重建）**

- 按「邮箱优先、用户名兜底」匹配：已有用户只更新资料/权限字段（公司、电话、角色等），**当前密码、头像、登录状态一律不动**
- 备份里有而本地没有的用户 → 整行插入并**保留原用户 ID**（后续恢复模型库等模块时创建人外键能正确对上），用备份时的密码登录
- 邮箱/用户名被其他账号占用（换绑撞名）→ 保留现状并记日志，**绝不把别人的账号改写成备份用户**，也绝不让单个冲突导致整个恢复失败
- 执行恢复的管理员自身跳过「禁用/降权」改写，不会被备份锁死

**数据安全五项加固（备份/恢复链路）**

1. **恢复进入数据写入阶段后禁止取消**——此前模块恢复中途点「停止恢复」可能留下文件目录半换、数据库与文件不一致的状态
2. **硬中断救援**——恢复中断电/OOM/强杀后，重启时提供一键回滚到恢复前快照的入口（与整站恢复同款双保险）
3. **取消路径清理救援标记**——防止残留标记误导管理员误点回滚，把正常业务写入回滚掉
4. **保留策略按类型分组 + 整站备份豁免**——小而频繁的模块备份不再挤掉唯一的整站备份（外部镜像目录同步同规则）
5. **导入确认文案按备份类型区分**——模块备份的恢复范围告知不再误写「覆盖全部数据」

**其他**

- 询价金额字段（total_amount / unit_price）备份恢复精确往返，无精度损失
- 模块备份/恢复全链路通过边角场景实测：换绑撞名、删除后恢复、空表恢复、取消中断、硬中断救援、保留策略触发

**建议升级后验证**：设置 → 备份 → 创建一个「用户」模块备份；恢复它并确认自己密码未变；备份列表查看新的统计卡片。

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**无数据库迁移**，直接升级：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v4.3.0 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v4.3.0
```

升级后注意：

- 旧版本（≤v4.2.1）服务器无法恢复新版本创建的用户/工单/询价/审计模块备份（会报备份包无效）——先升级服务器再导入
- 新的保留策略：整站备份不再被自动清理，模块备份按类型各自保留设定的份数——如需调整在设置页修改保留数量
- 用户模块恢复采用合并语义：已有账号密码不变，仅当账号在本地不存在时才使用备份中的密码

默认跟随 latest 的部署由 Watchtower 自动更新。
