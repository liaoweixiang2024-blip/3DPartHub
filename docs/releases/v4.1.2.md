## 更新标题

3DPartHub v4.1.2 - 安全修复：角色变更即时生效（JWT 角色快照绕过 + 禁用账号顶下线失效）+ 开关入口补漏

## 标签描述

3DPartHub v4.1.2 is a security-hardening patch. Root cause: several identity checks trusted the role baked into the 7-day JWT instead of the database, and a Redis key-prefix mismatch silently disabled token revocation — so demoting a user (e.g. INTERNAL → VIEWER) or disabling their account did not take effect until the old token naturally expired. Fixes: category-access and attachment/batch-download identity resolution now reads the live DB role (via getVerifiedRequestUser, which also checks the revocation list); revoked-token and rate-limit Redis writes now use the correct key prefix so "revoke on role change / disable" actually works; disabled accounts are rejected in both getVerifiedRequestUser and the refresh endpoint; the drawing-token endpoint now enforces category restrictions (it previously issued tokens for restricted models). Frontend: /reset-password is gated by the password-reset toggle, and the "request model" link in both theme templates plus the "go to selection" empty-state link now respect their feature toggles (theme sandbox compliance via a supportEnabled prop). Also: the no-op service-worker fetch handler was removed (Chrome no longer requires it for installability) and the routine THREE.js "Context Lost" log emitted on viewer teardown is suppressed within a 2s window (real context-loss errors still surface). No DB migration.

## 更新描述

本次为**安全修复**，无数据库迁移。核心问题：**改角色/禁用账号后权限不会立即生效**——多个权限判定点直接信任了 JWT 里的角色快照（签发时烧入，7 天有效），而且「改角色即顶下线」的令牌作废机制因 Redis 键前缀不一致**从未真正生效过**。

**修复一览**

- 分类访问控制改用**数据库实时角色**判定（不再信任 JWT 快照）——降级用户刷新页面立即按新角色生效
- 修复 Redis 键前缀不一致：令牌作废（改角色/禁用即顶下线）与登录限流计数此前一直写错键空间，现已统一，**改角色/禁用立即踢下线**
- 禁用账号两处缺口补齐：API 认证与 refresh 续签均拒绝禁用账号（此前禁用用户的旧会话最长还能用 7 天）
- 图纸访问令牌接口补分类访问拦截（此前受限模型仍可领图纸令牌）
- 工单/询价附件、批量打包下载的身份判定改查库（降级/禁用的前管理员旧 token 不再能看任意附件）
- 前端开关入口补漏：/reset-password 页接密码重置开关；classic/workbench 两套主题首页空状态「请求模型」接工单开关；我的询价空状态「去选型」接选型开关
- 移除 Service Worker 的空 fetch 监听器（Chrome 已不要求，消除控制台提示与每次导航开销）；静默 3D 查看器**正常卸载**时的 Context Lost 清理日志（真实异常仍正常提示）

**建议升级后验证**：把测试账号从某角色降级 → 刷新页面，受限内容应立即消失；禁用账号 → 其所有会话立即失效。

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**无数据库迁移**。升级步骤：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v4.1.2 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v4.1.2
```

升级后注意：

- **本次升级会触发全员重新登录**（令牌作废机制修复后，历史遗留的作废记录开始生效）——属预期行为，提前告知用户即可
- 建议验证：降级测试账号 → 刷新页面受限内容立即消失；禁用账号 → 会话立即失效

默认跟随 latest 的部署由 Watchtower 自动更新。
