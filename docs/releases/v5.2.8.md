# v5.2.8

发布日期：2026-09-30

## 更新标题

3DPartHub v5.2.8 - 文件下载断点续传加固（ETag/Last-Modified/If-Range 验证器）+ 下载流错误可见化（大文件下载被网络打断后可靠续传，不再整单从零重下）

## 标签描述

v5.2.8 hardens file downloads for large archives (GB-scale backups) so that a network interruption resumes instead of restarting from zero. The accelerated download path previously sent no validators (ETag / Last-Modified); after a connection drop, some browsers and download managers (Safari, ThunderXunlei/IDM) cannot confirm the resource is unchanged and give up on resuming entirely — re-downloading the whole file from the start, which users experienced as "the download nearly finished, then started over". Responses now carry a strong ETag (size + mtime) and Last-Modified, and If-Range is handled per RFC 7233: a matching validator returns 206 partial content for resume, a mismatching one falls back to a full 200 so clients never stitch mismatched halves into a corrupt file. Additionally, read-stream errors during download were silently swallowed (stream destroyed, response ended short of Content-Length — a truncated file could be saved as a "successful" download with nothing in the logs); they are now logged and the connection is destroyed so the client clearly sees the interruption and triggers ranged resume. Applies to all accelerated downloads (backup archives, model files, drawings). No database migrations.

## 更新描述

本次为 **下载断点续传加固** 版本，无数据库迁移，仅需更新服务端镜像（客户端无代码变更，随镜像一并发布保持版本号一致）。

## 下载断点续传加固

### 问题

- 备份等大文件（GB 级）下载到快完成时被网络抖动打断，浏览器/下载工具**放弃续传、整单从零重下**：响应缺少 ETag/Last-Modified 验证器，客户端无法确认文件未变化，按规范只能重新完整下载
- 下载读流出错被**无声吞掉**：流被静默销毁、响应以短于 Content-Length 的「正常结束」收尾，客户端可能把截断文件当下载成功保存，服务端日志毫无痕迹

### 修复

- **补齐续传验证器**：所有加速下载响应（备份/模型/图纸）带 `ETag`（size+mtime 强验证器）+ `Last-Modified`
- **If-Range 正确分支**（RFC 7233）：验证器匹配 → 206 续传；不匹配 → 200 整单，杜绝新旧两段拼出坏文件
- **流错误可见化**：读流失败记 error 日志（含文件路径）并直接掐断连接，客户端明确感知中断并走断点续传恢复

### 验证

- 五项 curl 实测全绿：完整下载字节精确 / 裸 Range 206 / If-Range 匹配 206 续传 / 不匹配回 200 整单 / 完整尺寸一致
- 超时说明：链路超时均为「静默间隔」计时（非总时长），几十 GB 下载数小时不受影响；下载令牌 24h 有效期内可无限次续传

## 升级说明

- 无数据库迁移（schema 未变更）
- 服务器更新：`docker-compose pull && docker-compose up -d`；验证：管理端下载一个备份，中途断网/暂停后恢复，下载应从断点继续而非从零开始（迅雷/IDM 的多线程续传同样受益）
