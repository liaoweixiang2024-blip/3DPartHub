## 更新标题

3DPartHub v3.5.4 - v3.5.3 安全修复的补充加固（删用户业务记录预检 / 角色缓存即时失效 / 远程图片流清理 / 登录清零顺序）

## 标签描述

3DPartHub v3.5.4 is a **follow-up hardening patch** to v3.5.3, fixing four issues found in a re-review of the v3.5.3 changes. No DB migration, no breaking change, no new feature.

1. **[Medium] Delete-user now pre-checks business records (FK Restrict tables)**: v3.5.3 only pre-checked models/versions (which cascade). But `SupportTicket`/`Inquiry`/`SelectionShare` are FK `Restrict` — deleting a user who filed a ticket/inquiry hit a raw `P2003` and returned an opaque 500. Now pre-checks these and returns a clear 400 "use disable account instead", with a `P2003` fallback for any other restrict table.
2. **[Medium] Role change now invalidates the 60s user cache**: `getVerifiedRequestUser` caches `{id, role, mustChangePassword}` for 60s. v3.5.3's `revokeAllTokensBefore` invalidated tokens but not the cache, so a demoted ADMIN could re-login and still pass `requireRole('ADMIN')` for up to 60s. All admin role/disable/reset-password/batch/delete paths now also `cacheDel('auth:user:{id}')`.
3. **[Low] Remote-image fetch now drains the response stream on failure**: `fetchRemoteImageGuarded` returns a raw `http.IncomingMessage`; on `!ok`/bad-format/over-limit early-returns the body was never consumed, holding a socket for up to 15s. All early-returns now call `resp.body.resume()`.
4. **[Low] Login failure counters no longer cleared for disabled accounts**: the order was verify-password → clear counters → check disabled. An attacker holding a disabled account's credentials could repeatedly "log in correctly → clear the IP failure counter" to reset the per-IP brute-force window. Disabled check now runs before clearing counters.

Also confirmed in re-review (no change needed): JWT enforcement, attachment allowlist, `nosniff`/disposition, share ownership, email-code rate limit, login IP dimension, SVG cloud CSP, SSRF core, `removeExistingFiles` path containment — all correct, no regression.

Verified: server 142 unit tests green. No DB schema change, fully backward compatible, no deployment prerequisite (the JWT requirement was already enforced in v3.5.3).

## 更新描述

本次是 **v3.5.3 安全修复的补充加固**，修复复审 v3.5.3 时发现的 4 个问题。不含功能变更、不含数据库迁移、**无破坏性变更**（`JWT_SECRET` 强制要求已在 v3.5.3 生效，本次无新增部署前提）。

- **[中] 删除用户的业务记录预检**：v3.5.3 只预检了模型/模型版本（这些是级联删除）。但工单、询价、选型分享与用户的关联是「禁止删除」（FK Restrict）——删除提过工单/询价的用户会撞数据库约束，之前返回无意义的 500。现已预检这三类业务记录，命中时返回明确提示「该用户存在工单/询价/选型分享，建议改用禁用账号」，并保留兜底处理其他 Restrict 关联表。
- **[中] 角色变更后立即刷新权限缓存**：服务端对「已验证用户」有 60 秒缓存。v3.5.3 的撤销令牌使旧 token 失效，但没清这个缓存——被降级的管理员重新登录后，最长 60 秒内仍可能被当作管理员放行。现已在管理员「改角色 / 禁用 / 重置密码 / 批量操作 / 删除」的所有路径上同步清除该用户的缓存条目，权限变更即时生效。
- **[低] 远程图片拉取失败时回收连接**：v3.5.3 新增的远程图片拉取在「下载失败 / 格式不符 / 超限」提前返回时，没有消费响应流，每个失败请求会占着一个网络连接最多 15 秒。现已在所有提前返回处释放响应流。
- **[低] 登录失败计数对禁用账号不再清零**：原先顺序是「密码正确 → 清失败计数 → 再查是否禁用」。攻击者若掌握某禁用账号的凭据，可反复「用对密码登录 → 清空同 IP 的失败计数」来重置暴破窗口。现已改为先查禁用（禁用账号不清计数直接拒绝），通过后才清计数。

复审同时确认 v3.5.3 的其余 9 项修复（JWT 强制、附件白名单、下载 nosniff、分享所有权、邮箱码限流、登录 IP 维度、SVG 云 CSP、SSRF 核心、文件删除路径校验）均正确、无回归。

## 部署备注

本次**无破坏性变更、无数据库迁移**（`JWT_SECRET` 强制要求已在 v3.5.3 生效，已设置强密钥的站点无需再做任何事）。直接升级即可：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.5.4 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health
curl -s http://localhost:3780/api/settings/version   # 应显示 v3.5.4
```

若你尚未升级到 v3.5.3（仍在 v3.5.2 或更早），可跳过 v3.5.3 直接升 v3.5.4——本版已包含 v3.5.3 的全部修复。但**首次从 v3.5.2 及更早升级前，仍须确认 `.env` 的 `JWT_SECRET` 已是强随机值**（v3.5.3 起强制要求）。

默认跟随 latest 的部署由 Watchtower 自动更新。
