## 更新标题

3DPartHub v3.2.0 - 企业级备份与部署验收版

## 标签描述

3DPartHub v3.2.0 enterprise release with pure Docker deployment verification, backup/restore/import drill evidence, hardened Docker runtime defaults, static asset self-healing, and refreshed GHCR images.

## 更新描述

- 备份能力进入企业级验收闭环：创建备份、导入备份、恢复备份均已在纯 Docker 生产编排中完成演练，恢复前后数据库业务指纹和资源文件指纹保持一致。
- 新增部署健康自检、证据包采集和生产验收脚本，覆盖 Compose 配置、生产密钥、容器健康、运行镜像、端口暴露、日志轮转、非 root 运行、停止宽限期、备份恢复演练证据、敏感静态路径保护和日志错误扫描。
- 修复 Docker 生产镜像启动时 `/app/static/product-wall`、备份工作目录、临时预览、图纸、选型资源等运行目录权限不足导致 API unhealthy 的问题。
- 修复 Web 容器 healthcheck 在部分 Alpine/Nginx 环境中使用 `localhost` 误判 unhealthy 的问题，改为明确探测 `127.0.0.1/healthz`。
- 修复 Docker 29 / Docker Desktop 下停止宽限期字段读取差异，部署自检可正确识别 `StopTimeout=300s`。
- API 容器去除多余 init 包装，主进程以 `node:node` 运行，降低生产容器 root 进程风险。
- 新增 API 镜像启动脚本，自动补齐缺失的默认 logo/favicon 静态资源，避免 Docker 命名卷遮住镜像默认资源后产生 `/static/logo/icon.svg` 404 和 Nginx error 日志。
- 备份恢复演练排除恢复动作本身新增的审计日志，避免 `audit_logs` 正常写入导致业务数据恢复校验误报失败。
- 分模块备份、真实资源统计、图库/选型/规格数据覆盖、临时 STEP 看图、安全上传限制、移动端 Safari/PWA 下载退出能力、产品图库性能优化等此前修复继续包含在本版本镜像内。
- 发布前验证包含前后端构建、部署工具回归、纯 Docker 生产栈健康检查、备份恢复演练和生产证据包验收。
- 镜像已同步更新：api/web 均发布 v3.2.0 与 latest 标签。

```bash
# 默认部署跟随 latest，并由 Watchtower 自动更新 api/web 镜像。
# 需要立即更新时执行：
cd /opt/3dparthub
curl -L -o docker-compose.yml https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/docker-compose.yml
touch .env
grep -q '^IMAGE_TAG=' .env && sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=latest/' .env || echo 'IMAGE_TAG=latest' >> .env
docker compose pull
docker compose up -d --force-recreate

# 快速健康检查
curl http://localhost:3780/api/health

# 只读部署自检并生成报告
curl -fsSL -O https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/scripts/deploy-health-check.sh
sh deploy-health-check.sh --report deploy-health-report.txt --json deploy-health-report.json

# 采集脱敏证据包用于支持和最终验收
curl -fsSL -O https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/scripts/collect-deploy-evidence.sh
sh collect-deploy-evidence.sh
```

把 `deploy-evidence-*.tar.gz` 和同名 `.sha256` 回传到仓库后可执行：

```bash
npm run deploy:acceptance -- deploy-evidence-YYYYMMDD-HHMMSS.tar.gz
npm run deploy:report:verify -- deploy-evidence-YYYYMMDD-HHMMSS.tar.gz --max-age-hours 24 --summary deploy-health-acceptance.md --summary-json deploy-health-acceptance.json
```
