# v5.5.3

发布日期：2026-10-10

## 更新标题

3DPartHub v5.5.3 - 修复更新版本后被登出（已轮换 refresh token 重放改为自愈换发，移除误伤级联吊销）

## 更新描述

修复用户报告的「更新版本后登录的账号（含勾选记住登录）全部退出登录」。根因是刷新令牌轮换的「宽限窗外重放判定为疑似泄露并级联吊销该账号全部令牌」逻辑：强刷掐断轮换响应、PWA 独立 cookie 罐隔天打开、设备休眠超过宽限窗（120s）等真实用户场景全都表现为「卡死在已轮换旧令牌上的 cookie 罐」，旧逻辑把它们当攻击者处置，每次都全量登出。本次将已轮换旧令牌的重放一律按「过期旧罐」自愈换发新令牌，登出语义改由独立的 revoked 标记保障（登出过的令牌重放仍被拒绝）。仅服务端改动，无数据库迁移。

## 修复清单

### 1. 已轮换旧令牌重放：级联吊销 → 自愈换发（核心修复）

- **现象**：更新版本（或强刷后隔一段时间再访问、隔天打开 PWA）后，勾选了记住登录的账号被登出；多设备/多账号一起中招
- **根因**：refresh 轮换时旧的 family 标记为已用；浏览器 cookie 罐若卡死在旧令牌上（强刷掐断上一次轮换的 Set-Cookie 等），超过 120s 宽限窗后的下一次刷新被判「疑似泄露重放」→ `revokeAllTokensBefore` 级联吊销该用户全部令牌 → 全设备登出。更新版本时按发版说明强刷浏览器，正好批量制造了这种卡罐，首次访问即被引爆
- **修复**：已轮换旧令牌的重放不再判定为泄露，一律换发新 family cookie（自愈）——无论宽限窗内外。攻击者偷到当前令牌在 120s 宽限内重放本来就拿到新会话，宽限外吊销实际只惩罚合法用户；真正的泄露处置通道全部保留（改密 / 密码重置 / 管理员改角色 / 禁用仍全量顶下线）

### 2. 登出语义改由独立 revoked 标记保障

- 登出从复用「已轮换」标记改为写独立 `refresh_family_revoked` 标记；refresh 端点见到 revoked 标记一律 401，登出过的令牌不得复活
- 附带修正：单设备登出不再清算其他设备/浏览器/PWA 的独立 cookie 罐（旧逻辑登出即全设备下线）
- 修复一处隐患：revoked 标记由 eval 写裸字符串，读取绕过 `cacheGet` 的 JSON 解析直接做存在性判断，避免字符串比较静默失配

## 升级说明

- 无数据库迁移（schema 未变更）
- 服务器更新：`cd /opt/3dparthub && docker-compose pull && docker-compose up -d`，浏览器强刷一次
- 本次仅服务端有实质改动（client 版本号同步递增）
- **已被登出的账号需要重新登录一次**（级联吊销标记最长保留 30 天，旧令牌无法复活）；本次部署后该类登出不应再发生
