## 更新标题

3DPartHub v4.6.0 - 后台品牌图片上传体验修复（换图即见 + 消除整页按钮联动跳动）

## 标签描述

v4.6.0 polishes the admin brand-asset upload experience. Brand images (site icon / logo / favicon / watermark) use fixed filenames and are replaced in place, so the uploaded URL never changed and browsers kept serving the cached response — including the 404 cached during the v4.5.11 nginx routing bug — leaving the settings preview stuck on a placeholder even though the file was uploaded fine. The upload endpoint now returns the URL with a version query (?v=timestamp), so every replacement busts the cache and the preview updates immediately. Also fixes a shared-upload-state layout jump: a single page-wide boolean drove every image-upload button across both setting groups, so clicking one "Replace image" turned ALL buttons into the wider "Uploading..." label at once and shoved sibling elements around; the state now tracks which setting key is uploading, so only the clicked button changes while others stay put (still disabled to prevent double submits). No database migration.

## 更新描述

本次为 **后台品牌图片上传体验修复** 版本，无数据库迁移。

**① 修复：更换品牌图片后预览一直显示占位图**

- 品牌图片（站点图标 / Logo / Favicon / 水印）用**固定文件名**同名覆盖换图，URL 不变——浏览器沿用旧缓存（包括此前 nginx 路由缺陷期间被缓存的 404 响应），表现为「上传成功但后台预览始终占位图」
- 修复：上传接口返回 URL 附带 `?v=<时间戳>`，每次换图 URL 变化强制重新拉取，预览**立即**显示新图

**② 修复：设置页图片上传按钮「一起跳动」**

- 原因：整页共享一个上传中布尔状态，点击任一「更换图片」会让**两处设置组的所有上传按钮**同时变为「上传中...」（文案变长按钮变宽），同行元素被推移产生联动跳动，上传结束又弹回
- 修复：状态改为记录「当前正在上传的设置项」，只有被点击的按钮进入上传中态，其余按钮保持原样（仍禁用以防重复提交）
