## 更新标题

3DPartHub v4.5.0 - 下载文件名中文化 + 通知浮窗清除已读持久化 + 备份/恢复三处加固 + 批量上传分类解析修复

## 标签描述

3DPartHub v4.5.0 makes downloaded archive filenames human-readable, fixes the notification panel's clear-read behavior, hardens three backup/restore edge cases, and fixes batch upload category resolution. Downloaded ZIPs are now named in Chinese with count and date — 收藏打包*12个文件\_20260903-1542.zip (favorites bundle), 下载打包*...zip (download history), 批量下载*...zip (admin batch), and backup archives download as 备份*全量*3331条\_20260903-1542.tar.gz (module + count + date). Encoding safety: all responses carry RFC 5987 dual headers (ASCII fallback name + UTF-8 filename*), so no browser ever sees mojibake — worst case an old browser falls back to an ASCII name; admin batch ZIPs keep ASCII on disk (URL path segment safety) and only translate to Chinese at download time; the client now parses the filename* segment first. Notification panel: clear-read previously only filtered in memory (v4.2.1's cautious change), so read items reappeared on refresh; cleared ids are now remembered in localStorage (capped at 500, oldest dropped) — the panel stays clean across refreshes while the full history page keeps every record (real deletion stays there). Backup/restore hardening: the restore-in-progress marker is now cleared only after file directories are committed (previously cleared after DB import, leaving the file-replacement phase unprotected against hard crashes — DB new/files half-old with no rollback entry); detectInterruptedRestores additionally reports leftover .restore_backup*\* directories (a new clear-leftover-restore-dirs endpoint cleans them); module backup payload exports are wrapped in a single $transaction so concurrent writes during backup can no longer produce cross-table inconsistencies (e.g. favorites referencing unread models → FK errors on restore). Batch upload fix: when a ZIP's root folder name matches an existing subcategory (e.g. 配件/水枪 subtree uploaded as 水枪/零件/文件), category resolution previously missed it (models landed uncategorized or in a duplicate auto-created root); resolution now falls back to matching any existing category by name before auto-creating. Also: backup records no longer show the always-zero "N 张预览图" stat (thumbnail counting fixed to include .jpg alongside .png in logs); the selection page no longer renders result-card checkboxes when the inquiry feature is disabled (clicking them previously triggered the "已加入询价清单" toast). No DB migration.

## 更新描述

本次为**体验优化 + 修复**版本，无数据库迁移。

**① 打包下载文件名可辨识（中文 + 数量 + 日期）**

| 下载入口            | 新文件名                                |
| ------------------- | --------------------------------------- |
| 我的收藏 → 打包下载 | `收藏打包_12个文件_20260903-1542.zip`   |
| 下载历史 → 打包下载 | `下载打包_8个文件_20260903-1542.zip`    |
| 管理后台 → 批量下载 | `批量下载_12个文件_20260903-1542.zip`   |
| 备份记录 → 下载     | `备份_全量_3331条_20260903-1542.tar.gz` |

之前是 `favorites_1788394123456.zip`（毫秒时间戳）和 `backup_1788…_ab12cd34.tar.gz`，完全看不出内容、日期、数量。

**编码兼容性三层保障（不会出现乱码）**：响应头同时带 ASCII 回退名和 UTF-8 `filename*` 段——现代浏览器显示中文，极老浏览器退回英文名，任何情况不乱码；管理端 ZIP 的磁盘文件名保持 ASCII（URL 路径段安全），下载瞬间才映射中文展示名；前端优先解析 `filename*` 段。

**② 通知浮窗「清除已读」不再复活**

之前清除已读后刷新页面，已读通知全部回到浮窗列表（内存过滤未持久化）。现在已清除的通知 id 记在本机（上限 500 条），刷新/重开浮窗都不再显示；**「我的通知」页保留完整记录**（那里的删除才是真删）。

**③ 备份记录去掉「0 张预览图」**

该统计口径已失效（缩略图格式从 png 全部转为 jpg，只数 png 恒为 0），从备份列表和恢复提示中移除；后端统计逻辑同步修正。

**④ 选型页：关闭询价功能后不再弹「已加入询价清单」**

结果卡的选择复选框此前未判断询价开关，勾选即触发加购弹窗；现在关闭询价时复选框不再渲染（桌面/移动端都修）。

**⑤ 备份/恢复三处加固**（深度审查 7 类中断/丢失场景，常规操作本无数据丢失风险，加固三个边缘场景）

1. **恢复中断保护窗口扩大**：恢复中断标记此前在数据库导入完成后即清除，其后的文件目录替换阶段（约 70%–94% 进度）若遇断电/OOM，会留下「数据库新、文件半旧」且无回滚入口。现在标记推迟到文件目录也提交完成才清除
2. **残留旧目录可发现**：启动检测新增扫描文件替换阶段的 `.restore_backup_*` 残留目录（即使无标记也能发现），新增清理接口 `clear-leftover-restore-dirs`
3. **模块备份事务化**：各表导出包进同一数据库事务，备份期间的并发写入不再可能产生跨表不一致（此前可能出现收藏引用未读到的模型，恢复时报外键错误）

**⑥ 批量上传分类解析修复**

ZIP 根层名是既有**子分类**时（如把「配件/水枪」子树打成 `水枪/零件/文件` 上传），此前模型会归不到分类或误建同名根分类；现在解析时先按名称全局匹配既有分类（任意层级），命中即挂入。本轮 300+ 模型批量上传中实战验证。

## 部署备注

```bash
cd /opt/3dparthub
docker-compose pull
docker-compose up -d
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）
```

默认跟随 latest 的部署由 Watchtower 自动更新。本次无 docker-compose.yml 改动，无 DB 迁移。

**建议升级后验证**：收藏页打包下载看文件名；通知浮窗清除已读后刷新页面确认不再回来；（管理员）备份页下载一个备份看文件名。
