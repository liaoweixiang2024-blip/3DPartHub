# v5.4.8

发布日期：2026-10-09

## 更新标题

3DPartHub v5.4.8 - 外层代理零配置化（文件服务下发 X-Accel-Buffering: no，独立反代免特殊设置直接可用）

## 更新描述

本次让**独立代理服务器（宝塔/nginx 反代）不再需要任何特殊配置**：源站对全部文件服务路径下发 nginx 标准信号 `X-Accel-Buffering: no`，外层代理收到后对该响应**自动关闭缓冲**——此前必须在代理上手配 `proxy_buffering off` 才能避免大文件下载被缓冲掐流（历史上「1GiB 缓冲掐流」的坑），现在源站直接免疫。配合既有的分片上传（默认 5MB/片，天然低于反代默认体积/超时限制），代理服务器只需最普通的反代 + HTTPS 证书即可。纯 nginx 配置改动，无数据库迁移、后端代码零改动（api 镜像仅版本号随动），更新 web 镜像即生效。

## 改动清单

### 1. 文件服务响应下发 X-Accel-Buffering: no（5 个 location）

覆盖全部文件下发路径，任何 nginx 外层收到该头都会对当次响应关缓冲（`proxy_buffering` 的标准上游控制信号，除非外层显式 `proxy_ignore_headers`）：

- `location /api/` —— 普通 API 响应与 Node 直连流（备份导出、批量 zip）
- `location ^~ /_protected_static/` / `location ^~ /_protected_uploads/` —— X-Accel 加速下载（模型 glb/图纸/附件）的最终出口
- `location /static/models/` —— 模型 glb 直连
- `location /static/` —— 缩略图/选项图等静态文件

### 2. nginx 合同检查同步加固

`client/scripts/verify-nginx-contract.mjs` 新增断言：上述 5 个 location 必须持续下发 `X-Accel-Buffering "no"`，防将来改配置时丢失。

## 验证

- Docker 起生产同构拓扑（web nginx + 伪 api 发 X-Accel-Redirect）实测四类路径（加速下载 / 普通 API / static 代理 / static alias）全部带 `X-Accel-Buffering: no` 响应头
- 回归矩阵不回退：根级固定名文件仍 must-revalidate / 哈希 assets 仍 immutable / version.json、index.html 仍 no-store / 加速下载仍返回真实文件内容 / 内部路径外部直访仍 404
- client `npm run verify` 全绿（含 nginx 合同检查新断言）；server 无代码改动 verify 全绿；仓库根 `npm run verify:deploy` 全绿

## 升级说明

- 无数据库迁移（schema 未变更）
- 服务器更新：`cd /opt/3dparthub && docker-compose pull && docker-compose up -d`
- 本次仅 web 镜像有实质改动，api 镜像仅版本号随动，两端一并拉取即可
- 上线后代理服务器**无需任何动作**；若代理此前手配过 `proxy_buffering off` 可保留（双保险）也可移除（源站信号已接管）
- 代理服务器完整要求从此收敛为：普通反代 + HTTPS 证书 + 不开缓存（宝塔默认即满足）；源站 `.env` 建议 `TRUST_PROXY=2`（两跳链路取真实客户端 IP）
