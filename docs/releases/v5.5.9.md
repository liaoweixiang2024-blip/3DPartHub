# v5.5.9

发布日期：2026-10-13

## 更新标题

3DPartHub v5.5.9 - 选型管理「选项设置」搜索框宽度修复（输入搜索词不再被挤窄）+ 选项值反查弹窗产品批量管理（新增产品默认带首行数据、勾选批量删除、批量修改只作用于勾选行）

## 更新描述

选型管理页两项升级：① 「选项设置」弹窗里输入搜索词后，搜索框会被新出现的「N/M 个选项」计数徽章和视图切换按钮挤得非常窄——弹窗加宽一档，搜索框独占一行，无论输入多长都保持整行宽度；② 点选项卡「N 型」角标打开的选项值反查弹窗从只读升级为可管理：可直接新增产品（草稿行默认带首行数据，改完确认创建）、勾选行批量删除，批量修改改为必须先勾选、只作用于勾选的产品——此前批量修改会把该选项值下全部产品一起改掉，勾选部分行也会全部修改，容易误伤。全部为前端改动，无数据库迁移。

## 修复清单

### 1. 选项设置弹窗搜索框宽度（修复）

- **现象**：在「选项设置」弹窗选中字段后输入搜索词，搜索框立刻变得非常窄（被随后出现的计数徽章、视图切换、一键排序按钮挤压，仅剩几十像素）
- **修复**：弹窗宽度 `max-w-2xl`(672px) 加宽到 `max-w-3xl`(768px)；工具栏改为两行布局——字段选择 + 视图切换 + 一键排序一行，**搜索框独占第二行**（计数徽章跟在旁边），输入搜索词前后宽度稳定不变
- 实测：输入搜索词后搜索框宽度 650px+（修复前会被挤到约 50px）

### 2. 选项值反查弹窗产品批量管理（新功能）

点选项卡上的「N 型」角标打开的反查弹窗（查看使用该选项值的全部产品）新增三项管理能力：

- **新增产品**：底部「新增产品」按钮 → 表格顶部出现草稿行，**默认带首行（上一行）的全部数据**（型号/名称/参数列 + 图片/PDF/kit 组件静默携带）→ 手动修改后点 ✓ 或回车确认创建；当前选项值所在列锁定不可改（保证新行仍属于该选项值），Esc 或 ✗ 取消；打开时表格自动滚回顶部保证草稿行可见
- **批量删除**：每行新增勾选框 + 表头全选/清选（仅当前显示的行），「删除所选 (N)」→ 二次确认弹窗 → 删除，不可恢复
- **批量修改改为只作用于勾选行**（语义修正）：没勾选任何行时「批量修改」按钮禁用（处理器内再校验一次并提示「请先勾选要修改的产品」）；勾选 N 行后填值应用，只改勾选的产品——修复此前勾选部分行也会把该选项值下全部产品一起改掉的问题
- 勾选状态与新增草稿在关闭弹窗或切换选项值后自动重置，不残留
- 底部提示文案跟随状态切换（草稿编辑中 / 已选 N 行 / 批量修改展开 / 待选）

- client `npm run verify` 全绿（TypeScript + ESLint + 33 测试 + 格式检查 + 构建）；仓库根 `verify:deploy` 全绿
- Playwright 端到端实测（本地站，64 产品的选项值）：搜索框输入后 650px+ 稳定；未勾选时批量修改禁用；新增 2 个测试产品（默认带首行数据）→ 勾选 2 行批量改名 → 66 行中只有勾选的 2 行被改；批量删除清理后行数复原；全选显示「删除所选 (64)」；关闭重开勾选重置、批量修改回到禁用——全部通过

- 无数据库迁移（schema 未变更）
- 服务器更新：`cd /opt/3dparthub && docker-compose pull && docker-compose up -d`，浏览器强刷一次（Cmd+Shift+R / Ctrl+Shift+R）；iOS 主屏 PWA 需彻底退出重开（等更新横幅或强杀）
- 上线后验收：
  - 选型管理 → 产品管理 → 选中分类 → 更多设置 → 选项设置：选字段后输入搜索词，搜索框保持整行宽度不收窄
