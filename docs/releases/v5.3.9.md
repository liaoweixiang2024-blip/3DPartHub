# v5.3.9

发布日期：2026-10-07

## 更新标题

3DPartHub v5.3.9 - 选型页三问题再修：窄分辨率下选项多时搜索框/分享按钮仍被挤压（右侧控件锁定自然宽度）+ 移动端清空选项后首项选项卡被冻结头遮住一半（复核对齐改为对头部底边比较）+ PC 端选完最后一项结果偶发不往上滚（滚轮惯性吞掉揭示滚动，改为惯性结束后重试）

## 更新描述

本次为**选型页滚动/布局修复**版本，v5.3.8 用户反馈的三个遗留问题全部闭环。无数据库迁移（schema 未变更），只涉及前端，更新 web 镜像即可（api 镜像例行同步）。

## 改动一：窄分辨率下工具栏右侧仍被挤压（v5.3.8 修复的补强）

- **现象**：PC 端水枪选型到结果阶段（8 个字段全选 + 清空按钮），搜索框和「生成分类链接」还是被挤压变形；高分辨率机器正常，换一台分辨率不同的机器（如 1366@125% 缩放 ≈ 1093px 有效宽度）就复现
- **根因**：v5.3.8 只让左侧 chips「允许收缩」，但右侧容器仍是 `flex-1`（basis 0、先让位）——空间分配顺序上 chips（basis auto）先吃空间，右侧被压到内容宽度以下后靠 `flex-wrap` 换行变形。挤压是否发生取决于剩余空间，因此只在特定分辨率出现
- **修复**：桌面端右侧控件组改为 `flex-none` **锁定自然宽度**（搜索框/生成链接/全部分类在任何桌面宽度下都不再变形），左侧 chips 显式 `flex-1` 吃剩余空间、横向滚动看全部
- **验证**：768 / 900 / 1093 / 1280 / 1440 五档宽度实测，右侧控件组全部 480×36 单行、无换行、无压缩

## 改动二：移动端清空选项后首项选项卡被冻结头遮挡

- **现象**：移动端向导中途点汇总条「清空」，回到第一步时第一项选项卡被冻结头遮住一部分，看不到选项文字（带图片的选项更明显）
- **根因**（实测复现）：清空后步骤区滚动定位的「复核」逻辑只对**滚动容器顶边**比较、不对**冻结头底边**比较——移动端冻结头盖住容器顶部约 176px，步骤标题落在「容器顶以下、头底边以上」的夹缝时复核认为"没越界"不拉回。旧代码实测：清空后标题 132px / 首项 170px，全部压在冻结头（底边 225px）之下
- **修复**：
  - 三处复核/兜底的对齐判断全部改为对「冻结头底边」比较（桌面端头部高度为 0，行为不变）
  - 「清空」「重新选择」的回顶兜底滚动补上冻结头高度偏移（之前漏减，会把第一步钉在头底下）
  - 冻结头高度计算提取为模块级 `stickyHeaderOffsetOf`，三处调用点统一
- **验证**：水枪 5 字段选中 → 滚动 → 清空，旧代码首项 170px 被遮 ❌ → 新代码标题 253px / 首项 291px 完整可见 ✅；结果页清空/重新选择两条路径同样验证通过

## 改动三：PC 端选完最后一项结果偶发不往上滚

- **现象**：选到最后一个字段点选项，选型结果揭示时**有概率**不自动滚动上来，要手动滚
- **根因**：结果揭示滚动有「用户 260ms 内滚动过就不抢滚动」的防打扰守卫，但滚轮/触控板的**惯性事件**会持续几百毫秒刷新时间戳——「滚到最后一项顺手点击」时揭示滚动被惯性判定吞掉、直接放弃。A/B 实测：旧代码滚轮惯性中点掉最后一项，结果标题停在视口底沿 92% 处不动
- **修复**：守卫命中不再放弃，改为每 320ms 重试（最多 4 次），惯性结束即可滚到位；若结果顶部已进入视口上半区（用户自己已看到）则不抢滚动
- **验证**：滚轮惯性中点击最后一项，旧代码 3/3 不滚 ❌ → 新代码 3/3 滚动到位（结果标题 140px，上半区）✅
