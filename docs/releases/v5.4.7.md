# v5.4.7

发布日期：2026-10-09

## 更新标题

3DPartHub v5.4.7 - 紧急修复 v5.4.6 引入的加速下载 404（分享模型预览/图片附件打不开）

## 更新描述

本次为**紧急回滚式修复**：v5.4.6 新增的「根级固定名文件缓存头」正则 location 意外劫持了 nginx X-Accel-Redirect 内部路径，导致所有走加速下载的 `.glb/.png/.jpg` 等文件返回裸 404——表现为**点击分享链接模型预览加载失败**、模型下载 glb 格式失败、工单/询价里的图片附件打不开。纯 nginx 配置修复 + 新增防复发合同检查，无数据库迁移、后端代码零改动（api 镜像仅版本号随动），更新 web 镜像即生效。

## 问题与修复

### 现象

- 打开分享链接：控制台报 `GET /api/shares/<token>/model-preview 404`，3D 预览空白
- 工单/询价附件为图片时同样 404

### 根因（v5.4.6 回归）

nginx 的 X-Accel-Redirect 加速下载机制：API 校验权限后返回 `X-Accel-Redirect: /_protected_static/models/xxx.glb`，nginx 对该内部 URI **重新走一遍 location 匹配**后从共享卷取文件。v5.4.6 新增的根级缓存正则

```
location ~* ^/(?!assets/|static/|api/|uploads/)(?:[^/]+/)*[^/]+\.(...|glb|...)$
```

负向前瞻只排除了 `assets/static/api/uploads` 四个前缀，`/_protected_static/models/xxx.glb` 以 `.glb` 结尾、恰好落入该正则；而 **nginx 里正则 location 优先于普通前缀 location**，于是劫持了本该由 `location /_protected_static/`（internal）处理的内部重定向，跑到 web 根目录 try_files 找文件 → 裸 404。图纸 PDF、step/stp、zip 下载因扩展名不在正则列表而幸免。

### 修复（双保险）

1. 根级缓存正则的负向前瞻补上 `_protected_` 排除项
2. `location /_protected_static/` 与 `location /_protected_uploads/` 加 `^~` 修饰符——最长前缀命中后跳过正则检查，**任何将来新增的正则 location 都无法再劫持加速下载内部路径**（本仓库正则压前缀的第二次事故，第一次是 favicon alias 双重路径）

### 防复发

新增 `client/scripts/verify-nginx-contract.mjs` 并接入 `npm run verify`（CI 全量跑）：静态锁住 ^~/internal/排除清单/各缓存策略等坑位不变量。用 v5.4.6 旧配置反证过——脚本会精确报出缺失的 3 项。
