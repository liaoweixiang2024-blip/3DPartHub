## 更新标题

3DPartHub v3.4.5 - 首屏减重 + Redis 缓存诊断准确性修复

## 标签描述

3DPartHub v3.4.5 patch release. (1) Build: pin the 87KB legal-text module to its own chunk so it only loads on the legal/settings pages instead of every homepage first paint, cutting the homepage initial JS download by ~28KB gzip with no behavior change. (2) Fix the admin "测试 Redis" connectivity diagnostic to test the cache connection the application actually uses (env REDIS_URL via the shared cache client) instead of a separately-built client configured from possibly-empty/wrong redis_password DB settings — previously it could report WRONGPASS while the real cache was healthy, falsely implying caching was down.

## 更新描述

- 首屏减重：将法律文案（约 87KB，仅隐私政策/服务条款页使用）从首页首屏 JS 包中隔离到独立 chunk，首页首屏下载减少约 28KB（gzip），首次访问/强制刷新时首页加载更快。法律文案只在打开隐私/条款页时才加载。纯构建优化，无功能变化。
- 修复「测试 Redis」诊断误报：改为测试应用**实际使用**的缓存连接（REDIS_URL 环境变量），不再用数据库里可能填错或为空的 `redis_password` 设置去单独建连接测试。此前在真实缓存正常工作的情况下，诊断仍可能显示「WRONGPASS 失败」，让人误以为缓存没生效；现在诊断通过即代表首页接口（/api/models、/api/categories 等）正在使用的缓存连接确实可用。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

API image title: `3dparthub-api:v3.4.5`

API image description: Express/Prisma API service. v3.4.5 fixes the admin cache connectivity diagnostic (testCacheConnectivity) to exercise the real application cache connection (env REDIS_URL via cache.ts: cachePing + cacheSet/cacheGet/cacheDel round-trip) instead of a separately-configured ioredis client built from redis_url/redis_password DB settings, eliminating WRONGPASS false alarms while the real cache is healthy. No runtime caching behavior change. Includes all v3.4.4 hardening (category-icon backup regression test), v3.4.3 restore UX (one-click stop restore, live archive-scan progress, 20-minute manifest-read timeout), prior backup/restore/import hardening, secure temporary STEP previews, protected downloads, localized update flows, Redis/storage diagnostics, audit logs, queues, and production safety tooling.
