## 更新标题

3DPartHub v4.9.3 - 修复移动端标题卡「裸文本→卡片」跳动（主题样式断链）+ CSS 单文件化

## 标签描述

v4.9.3 fixes the mobile title-block flicker introduced with the route skeletons. The interface themes define every header-card property (background, radius, shadow) through CSS variables declared on an `.app-page` ancestor. The route-loading skeleton and the rebuilt 个人设置 header both lacked that ancestor class, so on first open the page title briefly rendered as bare top-left text before snapping into the themed card — the exact jump users reported on 我的收藏 / 我的工单 / 个人设置. Both containers now carry `app-page`, verified frame-by-frame in a production build: the header card is fully styled from the very first frame (previously unstyled for ~300ms+ on device). Additionally the client build no longer code-splits CSS (single stylesheet): lazy-loaded route stylesheets arriving after first paint caused the same class of flash; `vite preview` now proxies `/api` so production builds can be tested locally; and the app waits for the main stylesheet before first render as a defensive measure. Frontend-only release, no database migration.

## 更新描述

本次为 **移动端标题卡样式修复** 补丁，纯前端改动，无数据库迁移，前后端镜像均需更新。

**① 修复：首次打开标题先「裸文本贴左上角」再跳成卡片**

- 根因：主题系统把标题卡的背景/圆角等样式定义在 `.app-page` 祖先类的 CSS 变量上；v4.9.1 的路由加载骨架与 v4.9.2 重构的个人设置标题卡都缺了这个祖先类 → 变量断链 → 骨架期标题无卡片样式，页面挂载后才恢复（约 300ms 跳动，真机更明显）
- 修复：路由骨架与个人设置标题卡均补上 `app-page` 容器；生产构建逐帧实测首帧起即为完整卡片样式（97 采样点零裸样式）

**② CSS 单文件化（防同类闪变）**

- 构建改为不再按路由拆分 CSS（全站单样式表），杜绝懒加载路由的样式表晚于首帧到达导致的样式跳变；首屏 CSS 增加约 50KB（gzip 后更小）

**③ 工程加固**

- `vite preview` 与 dev 同源代理 `/api` 等路径，可本地预览生产构建复现真机问题
- 应用启动时等待主样式表就绪后再渲染（防御性，正常无感）
