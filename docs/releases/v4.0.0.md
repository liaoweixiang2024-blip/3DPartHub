## 更新标题

3DPartHub v4.0.0 - 备份系统大修：校验提速 + 进度透明化 + 断点续传（进入 4.x 大版本）

## 标签描述

3DPartHub v4.0.0 is a backup-system overhaul release marking the entry into the 4.x major series. No DB migration. Backup verification of large archives is dramatically faster and fully transparent: the manifest is now packed at the head of the archive (reading it no longer sequentially decompresses the entire database dump — minutes-to-tens-of-minutes becomes seconds), and database/module-data SHA256 verification switched to a streaming tar-pipe hash (half the IO, no temp-file extraction). Every deep-verification stage now reports progress (reading manifest / streaming hash with size hint / directory count check) so the UI no longer appears frozen after entry scanning. The restore pipeline's longest black-box stage (psql database import) now emits a heartbeat with elapsed time and SQL size every 5 seconds. Chunked upload UX is overhauled: explicit merging/starting phase messages instead of a dead 100% bar, upload and server-processing render as separate progress segments without percentage jump-back, and interrupted large-file uploads resume from where they stopped (uploadId + file fingerprint persisted, new GET /api/upload/status reports uploaded chunk indexes, identical-file selection shows a resume hint). Reliability fixes: syncJob now stamps updatedAt so completed jobs are retained for the intended 1 hour instead of being evicted immediately (a latent semantic bug), and import-save jobs are evicted like all other job types (fixes a slow memory leak). Module backup records now carry semantic itemCount/fileCount fields (the legacy fields stay for backward compatibility with existing records). Also fixes two pre-existing import-order lint warnings (UserEditDialog, RegionSelect) — lint is now clean end to end.

## 更新描述

本次为备份/恢复系统大修，**无数据库迁移**。作为 4.x 大版本的首发版。

背景：一次大备份（11975 个条目）在「正在校验备份包完整性... 已扫描 11975 项」后界面假死近 5 分钟——排查发现不是卡死，而是校验的深度阶段（读清单/校验数据库文件）完全没有进度上报，且读清单要从归档头顺序解压整个数据库。本轮把备份/恢复全链路的进度体验系统性修完：

**校验提速（根治假死源头）**

- manifest.json 打包时显式放在归档最前：读清单从「顺序解压整个库（大库最长 20 分钟）」降到秒级
- 数据库/模块数据文件 SHA256 校验改为流式管道哈希（tar xO 直接进哈希），不再解压落盘，IO 减半

**进度透明化（5 项进度条修复）**

- 校验深度阶段全部上报：读取清单 → 流式校验数据文件（带大小提示）→ 核对目录文件数，每步都有文案
- 恢复时最长的 psql 导入阶段（大库几分钟到几十分钟）每 5 秒心跳报「正在导入数据库（X GB）... 已用时 Ns」
- 分块上传合并/启动恢复阶段有明确文案，不再假死在 100%
- 上传与服务端处理拆为两段独立进度，切换不再从 100% 回跳
- 大文件分块上传支持**断点续传**：页面刷新/断网后重选同一文件自动从断点继续（已传分块不重传），并有提示

**可靠性修复**

- 任务状态统一盖 updatedAt 时间戳：终态任务正确保留 1 小时（原语义错误立即逐出，靠 /tmp 文件兜底）
- 导入保存任务补齐内存清理（修复缓慢内存泄漏）
- 模块备份记录新增语义化 itemCount/fileCount 字段（「资源文件数」不再冒充「缩略图」；存量记录展示兼容）
- 修复 2 个遗留 import 顺序 lint warning，全链路 lint 归零

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**无数据库迁移**。升级步骤：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v4.0.0 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v4.0.0
```

升级后注意：

- **旧备份包完全兼容**：manifest 不在头部的旧归档，校验时同样能通过（只是读清单仍需顺序解压，且现在有阶段性进度提示，不会假死）。
- 断点续传要求「同一个文件」（文件名/大小/修改时间都一致）且距上次上传不超过 4 小时（服务端会话 TTL）。
- 大备份的创建/校验耗时会有明显下降：读清单秒级返回 + 流式哈希省一半 IO。

默认跟随 latest 的部署由 Watchtower 自动更新。
