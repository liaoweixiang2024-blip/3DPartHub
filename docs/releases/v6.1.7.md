## 更新描述

### 1. 手机端弹窗显示不全修复（用户报告：用户编辑弹窗看不到确认/取消按钮、上下被切）

根因有两个：弹窗高度用 `vh` 计算（手机浏览器按「地址栏收起时的大视口」取值，地址栏可见时比屏幕还高，居中弹窗上下各被切一块）；弹窗层级 z-120/50 低于移动端顶栏（z-250），弹窗头部被顶栏盖住。本次统一按项目既有底部弹层模式修复 8 处：

- **用户编辑弹窗 / 新增用户弹窗**（管理后台-用户管理）：`dvh` 动态限高 + 移动端底部弹层 + `zIndex 10000` 盖过顶栏；表单区内部滚动，取消/保存按钮永远钉底可见
- **转换队列-任务详情弹窗**（管理后台-模型管理）：同款修复；z 取 260——盖过顶栏(250)但仍让面板内的重试/取消确认弹窗(10000)压在上面；顺带消掉内层 `calc(88vh-72px)` 魔法数（面板改 flex-col 结构）
- **询价分配弹窗**（管理后台-询价管理）：同款修复（z 260），确认转交按钮钉底
- **分类节点弹窗**（公共-分类选型导航）：`dvh` 限高 + 底部弹层（层级本已正确）
- **图片预览灯箱**（询价/工单详情页）：`90dvh` 防图片上下微裁 + z 260 盖过顶栏
- **模型管理列表容器**：`100vh`→`100dvh`（桌面行为不变）

### 2. 邀请制注册链路修复（用户报告：邀请链接点进去是登录页，切到注册邀请码也没了）

根因：站点关闭自由注册（`allow_register=false`，邀请制）后，代码三处都把「关闭自由注册」当成「完全禁止注册」——路由层 featureGuard 一刀切拦截注册接口（带有效邀请码也 403）、前端 `/register?invite=码` 被重定向到登录页（**邀请码参数丢失**）、登录页/弹窗在关闭注册时隐藏注册入口和邀请码输入框。被邀请人拿到链接后整条链路走不通。本次修复为邀请制正确语义——**凭码准入**：

- **服务端**：无邀请码 → 403 提示「注册功能已关闭，请使用邀请码注册」；带码 → 走既有校验（有效+未被使用+事务抢占标记 used）放行注册
- **前端路由**：带 `?invite=` 的链接不再跳登录页，直接渲染注册表单并预填邀请码
- **登录页/登录弹窗**：邀请码功能开启时保留注册切换入口；邀请码输入框在邀请制下必显示、必填；登录弹窗同样自动预填 URL 邀请码
- **管理后台设置文案**更新：「关闭自由注册；开启邀请码注册后，新用户仍可凭邀请码注册」

### 3. 工单支持页联系邮箱（用户报告：还显示 support@example.com 占位符）

工单提交页的「邮件支持」卡片此前硬编码占位地址。现改为读站点设置的「联系邮箱」（管理后台 → 系统设置 → 邮件配置 → 联系邮箱）；未配置时隐藏邮件卡片，不再显示假地址。

## 审计确认

- 无数据库 schema 改动、无新增迁移（prisma migrate status: up to date，61 migrations）、无新增依赖
- 服务端行为变更仅一处：`/api/auth/register` 的门禁从「featureGuard 无差别拦截」改为「handler 内凭码判定」——`allow_register=true` 时行为与原先完全一致（require_invite_code 只在开启时强制要码，原样保留）；`allow_register=false` 时从「全拒」放宽为「凭有效邀请码准入」，邀请码校验/一次一码抢占复用既有逻辑，无新增攻击面（无码仍 403）
- 摘除的 featureGuard 管理员 bypass 对注册接口无意义（重新开放注册走设置接口，不走注册接口）
- 客户端 z 层级调整全部低于既有最高档（Toast/确认弹窗 10000），不影响既有弹层叠放
