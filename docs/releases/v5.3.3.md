# v5.3.3

发布日期：2026-10-06

## 更新标题

3DPartHub v5.3.3 - 移动端选型大分类卡按住滑动「整卡变纯白」根治（iOS 合成层叠加半透明背景的渲染瑕疵：背景预压平为不透明色 + 移除列表容器残留的常驻合成层）

## 标签描述

v5.3.3 fixes the last mobile selection category-card artifact: while press-holding and sliding the category list on iPhone, the touched card turned pure white (brighter than its warm translucent siblings). This is a WebKit rendering behavior, not a CSS state: when iOS promotes the touched button into its own compositing layer, its semi-transparent background (`/45` alpha) composites against the layer's own white backing tile instead of the warm page background. Verified by emulated touch press-hold/drag in Chromium: computed styles stay completely unchanged through before/hold/drag/after, and the same white-out cannot be reproduced - it is iOS-only painting. Fix has two layers: (1) pre-flatten the card background, selected-state background, hairline border, and thumbnail-slot background into fully opaque colors via `color-mix(... , var(--color-surface))` - same blend formula as before, visually identical, but an opaque color physically cannot change under any compositing arrangement; (2) remove the leftover `transform-gpu` on the phase wrapper that kept the whole list on a permanent GPU layer. Desktop is unaffected (mouse hover/press feedback unchanged). No database migrations.

## 更新描述

本次为 **移动端选型触摸渲染瑕疵根治** 版本，无数据库迁移，更新前后端镜像即可。

## 根因：为什么 v5.3.2 之后 iPhone 上按住的卡还是变白

- 变白的卡是**纯白** (RGB 255,255,255)，其余行是米白半透明叠在暖色页面底上——不是选中高亮（无橙色左边条）
- 用 Chromium 触摸模拟按住 350ms + 拖动全程抓计算样式：背景/透明度/transform/will-change **全程零变化**，Chromium 里复现不出——纯 iOS WebKit 渲染行为
- 机制：iOS 触摸时会把按住的 button 提升为独立合成层，卡片背景是 45% 半透明色，提层后半透明色直接叠在**图层自身的纯白 tile** 上，盖过了页面暖底 → 整卡变白。这是 iOS 上「半透明背景列表 cell 滚动变白」的经典已知问题
- 帮凶：v5.3.2 删了卡片自身的 `transform-gpu`，但 phase 容器 `motion.div` 上还挂着一个 `transform-gpu`，整个列表常驻 GPU 合成层，放大了上述瑕疵

## 修复

| 位置                        | 改动                                                                                                                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| phase 容器（SelectionPage） | 删除 `transform-gpu`（入场动画期间 framer-motion 会临时建层，0.16s 后自动释放，不需要常驻层）                                                                                            |
| 卡片背景（global.css 变量） | `bg-surface-container-low/45` → `--selection-card-bg: color-mix(in srgb, surface-container-low 45%, surface)`——混色公式与原半透明完全一致（底色取根节点 `bg-surface`），但结果**不透明** |
| 选中态背景                  | `bg-primary-container/8` → 同法压平（选中瞬间同样会被提层）                                                                                                                              |
| 卡片分隔线                  | `border-outline-variant/12` → 同法压平（顶部分隔线显形同源）                                                                                                                             |
| 缩略图槽                    | `bg-surface-container-high/45` → 同法压平                                                                                                                                                |
| 桌面端                      | 不变（鼠标无触摸提层；悬停/按压动画、选中高亮照旧）                                                                                                                                      |

不透明的颜色在任何合成层状态下都不可能再变白/变深——这类瑕疵从根上灭绝。

## 验证

- Chromium 触摸模拟（iPhone 430px 视口）：修复后按住/拖动全程计算样式稳定，卡片计算背景为不透明色，祖先链 `transform-gpu` 清零
- 视觉对照：混色公式与原半透明版本一致（同样的 45% 叠加，只是预先算好），正常状态颜色无变化
