## 更新标题

3DPartHub v3.9.3 - 修复反代防护开启时容器不健康 + 页面顶部乱码

## 标签描述

3DPartHub v3.9.3 fixes two failures that surface when the anti-reverse-proxy guard (anti_proxy_enabled) is on and the visiting domain is not in allowed_hosts. 1) Container permanently unhealthy: the guard's health-check exemption matched only the exact path /api/health, but docker-compose probes /api/health/ready — the probe was 403'd, so the API container never became healthy and web never started. The exemption now prefix-matches /api/health and /api/health/\*. 2) Garbage at the top of the page on load: nginx's SSI include for the head fragment received the guard's 403 full-HTML warning page and spliced it into <head>, rendering stray markup above the site until React took over. The SSI subrequest location now intercepts all error statuses (403/404/429/5xx) and falls back to the build-time default head fragment. Note for deployments that hit issue 1: also verify allowed_hosts contains the domain you browse from, or the site itself stays blocked by design. No DB migration.

## 更新描述

本次修复**反代防护开启时的两个故障**：容器健康检查失败导致起不来、页面顶部闪乱码。无数据库迁移。

- **[修复] 开启「反代防护」后 API 容器一直不健康、整站起不来**
  - 根因：反代防护拦截未授权域名时，健康检查接口 `/api/health/ready` 也被 403（旧代码只豁免了 `/api/health` 精确路径），docker 健康探测永远失败 → api 容器被判不健康 → web 容器不启动。
  - 现在豁免 `/api/health` 与其所有子路径（ready/live）。
- **[修复] 打开网站时顶部出现一段乱码/无关内容，稍后恢复正常**
  - 根因：页面头部的服务端注入（SSI）子请求被反代防护以 403 返回了一整页「未授权访问」警告 HTML，nginx 把它拼进了页面 `<head>` 顶部；React 加载完成后接管渲染，乱码才消失。
  - 现在 SSI 子请求遇到任何错误状态码（403/404/429/5xx）都回退到镜像内置的默认头部片段，不再把错误页拼进页面。
- **提醒**：若此前因本问题无法启动，请确认后台「安全防护」的授权域名列表包含实际访问的域名，否则网站本身仍会被反代防护按设计拦截。

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## Docker Images

API image title: `3dparthub-api:v3.9.3`

API image: `ghcr.io/liaoweixiang2024-blip/3dparthub-api:v3.9.3`

API image description: Express/Prisma API service. v3.9.3 widens the anti-proxy ipGuard health-check exemption from the exact path /api/health to a prefix match covering /api/health/ready and /api/health/live, so container healthchecks pass even when the visiting host is not in allowed_hosts. No DB migration. Includes all v3.5.0–v3.9.2 functionality.

Web image title: `3dparthub-web:v3.9.3`

Web image: `ghcr.io/liaoweixiang2024-blip/3dparthub-web:v3.9.3`

Web image description: React/Vite frontend. v3.9.3 makes the nginx SSI head-fragment subrequest intercept all error statuses (403 404 429 500 502 503 504) via proxy_intercept_errors and fall back to the build-time default head fragment, preventing error/warning pages from being spliced into <head> (visible as garbage at the top of the page when the API's anti-proxy guard returned 403). No DB migration. Includes all v3.5.0–v3.9.2 functionality.

## 部署备注

本次**无数据库迁移**。升级步骤：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.9.3 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v3.9.3
```

升级后注意：

- 若当前容器因健康检查失败处于异常状态，本次升级后即可正常启动。
- 后台「设置 → 安全防护」若开启了「反代防护」，请确认授权域名列表包含实际访问的域名（如 www.yourdomain.com），否则网站访问仍会被按设计拦截。

默认跟随 latest 的部署由 Watchtower 自动更新。
