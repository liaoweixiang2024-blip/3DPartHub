# v5.9.7

发布日期：2026-10-21

## 更新标题

3DPartHub v5.9.7 - 工单支持拖拽/粘贴上传附件（格式放宽到文档/压缩包/CAD）+ 登录 IP 显示真实客户端地址（TRUST_PROXY 两跳）+ 图片墙预览自动修复 + 版本更新记录全量统计徽章

## 更新描述

本版补齐工单系统的附件能力并修三个使用中暴露的问题：① 技术支持页提交工单此前只能纯文字，现在支持拖拽/点选/直接粘贴截图上传附件，格式从仅图片放宽到文档/压缩包/CAD 文件（单个 ≤5MB、最多 5 个，与后台「工单附件」设置联动）；② 生产环境登录日志的 IP 全是代理服务器地址——trust proxy 按两跳链路（宝塔 → web 容器 nginx → api）配置后审计日志记录真实客户端 IP；③ 图片墙部分历史图片被「钉」在原图上导致滚动卡顿，现在读接口自动检测并后台重生成预览（本地实测 154MB 首屏降到 1.1MB）；④ 关于页「版本更新记录」新增全量统计徽章（共 N 次更新 / 大版本 / 小版本），统计 GitHub 全部 187 个正式 release 而非仅展示的 20 条。

## 变更清单

### 1. 工单创建支持附件（拖拽 / 粘贴 / 多文件）

- 后端 `/api/tasks` 支持 multipart：`files` 数组最多 5 个（TICKET_CREATE_ATTACHMENT_LIMIT），沿用 `ticket_attachment_max_mb` 大小上限与 `ticket_attachment_types` 白名单（默认放宽为图片/Office/PDF/txt/csv/zip/rar/7z/STEP/IGES/STL 等）；非 multipart 请求原样放行（JSON 兼容）
- 附件落盘为随机 UUID 文件名，创建后逐个生成为 `content=''` 的工单消息（不触发管理员通知轰炸、不引起状态流转）；创建失败/早退路径自动回收已落盘文件（multer 2.4 报错自带整批回收，源码确认）
- 附件访问：`/api/tickets/:id/attachments/:file` 需 JWT 或 5 分钟短时 token（绑定 工单ID:文件名），属主/管理员校验；响应强制 `Content-Disposition: attachment` + `nosniff`，白名单外的类型（含 SVG）一律 octet-stream 强制下载——无 inline XSS 面
- 前端技术支持页：桌面/移动拖拽区（拖入高亮）、粘贴截图（仅拦截 clipboardData.files 不影响文字粘贴）、附件 chips 可移除；超限/超大小/非法类型本地预检 + toast 提示；附件数量/大小/格式提示文案与后台设置实时一致（upload_policy 注入修复：此前提示写死 5MB 与设置脱节）
- 提交带附件自动切 multipart FormData；五语言（zh/en/ja/ko/de）文案同步

### 2. 登录 IP 显示真实客户端地址（TRUST_PROXY）

- 根因：生产链路两跳代理（宝塔反代 → web 容器 nginx → api 容器），Express trust proxy 此前按 1 跳配置，`req.ip` 取到的是 web 容器 nginx 的地址
- `TRUST_PROXY` 环境变量数字化解析（docker-compose 默认 2）；api 容器不发布端口（仅 web 暴露 3780），无法直连伪造 X-Forwarded-For
- 生效后新审计日志（登录/下载/变更操作）记录真实公网 IP；**历史日志不回填**（记录时已丢失）
- 验证方法：服务器更新后登录一次 → 管理后台「审计日志」看登录行 IP 是否为真实公网 IP；若仍是内网/代理地址，检查宝塔反代是否透传 `X-Forwarded-For`

### 3. 图片墙预览自动修复（滚动卡顿根治）

- 根因两个：① 历史遗留行 `preview_image_url` 为空或被粘性标记成原图本身，页面直接加载 2-4MB 原图；② 生成失败曾被标记为「就用原图」，永不重试
- 修复：生成失败不再粘性标记；读接口懒回填队列自动检测「无预览 / 预览=原图」的行，按批（12 个/批）后台重生成 640px JPEG 预览——**服务器更新后首次打开图片墙即逐步自愈，无需手工操作**；小图（<768KB）跳过生成且不重复写库
- 本地实测：154MB 原图列表首屏降到 1.1MB（约 140 倍）；模拟「钉原图」行读一次接口 3 秒内自动恢复
- 附离线修复脚本 `npm run product-wall:repair-previews`（幂等；生产镜像不含 scripts/，日常用读接口自愈即可）

### 4. 关于页版本更新记录全量统计

- 「版本更新记录」标题后新增三枚徽章：**共 N 次更新**（高亮）+ **大版本** + **小版本**（当前 187 / 39 / 148），统计 GitHub **全部正式 release**（翻页拉全量，服务端缓存 1 小时），不是仅展示的 20 条
- 大版本按 X.Y 系列分组（与发版规则一致），列表仍展示最近 20 条 + 「更多历史版本」跳 GitHub
- 「检查更新」按钮加载图标从旋转放大镜换成 Loader2 圆环
- 离线/限流兜底：统计拉不到时徽章隐藏，时间线不受影响

### 5. 选型导航页标题区块与其他页面统一

- classic 界面主题下 `/category-nav` 页头卡片被历史压缩规则压扁（矮 18px）且贴死屏幕边缘（publicLayout 无内边距兜底），与收藏/下载/分享页不一致
- 删除页头压缩覆盖（padding/min-height/两行截断），classic 主题补齐桌面 24px 页面内边距；workbench 主题不受影响（实测两主题 × PC/移动端页头几何全等）

## 服务器更新

```bash
cd /opt/3dparthub
docker-compose pull
docker-compose up -d
```

- **⚠️ 登录 IP 功能需补一行配置**：本版镜像内已支持 `TRUST_PROXY`，但服务器上的 `docker-compose.yml` 是旧模板建的、没有这个变量（`docker-compose pull` 不会更新 compose 文件本身）——不补的话 api 只信 1 跳代理，登录 IP 仍显示宝塔的地址。补法（自动备份原文件）：

  ```bash
  cd /opt/3dparthub
  sed -i.bak-597 '/NODE_ENV: production/a\      TRUST_PROXY: "2"' docker-compose.yml
  docker-compose config >/dev/null && echo YAML_OK
  grep -n TRUST_PROXY docker-compose.yml
  docker-compose up -d
  docker exec 3dparthub-api printenv TRUST_PROXY   # 应输出 2
  ```

  补完退出重新登录一次，审计日志的登录行应显示真实公网 IP（若显示 `172.x` 开头，说明宝塔反代未透传 `X-Forwarded-For`，需在宝塔反向代理配置补 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`）。仓库侧生产模板 `deploy/docker-compose.yml` 已随 `3d99fd3` 修好，以后重建服务器不会再踩

- 图片墙预览在首次有人打开图片页后自动逐步修复，无需手工操作
- 历史审计日志的 IP 不回填（记录时已丢失），自新登录起生效
