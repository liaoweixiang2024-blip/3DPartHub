# v5.5.8

发布日期：2026-10-12

## 更新标题

3DPartHub v5.5.8 - 选型进度保存全面升级（问询横幅「继续/重新开始」+ 永久草稿 + 跳出看模型 15 分钟内静默恢复）+ 修复选型页误弹「产品数量不能超过 500」+ 「重新选型」入口明确化

## 更新描述

选型页三项升级：① 修复用户没点分享却弹出「产品数量不能超过 500」——选型结果出现后页面会自动预创建工单来源分享快照，匹配结果超过服务端 500 上限时创建失败，后台任务的报错错误地弹给了用户；② 选型进度保存从 v5.5.7 的「自动恢复 + toast 提示」升级为「问询横幅」——主动进入时不再自动恢复，首页横幅展示上次选到哪、让用户选「继续 / 重新开始」，恢复与否交还用户；快照改为永久草稿（不过期），直到用户确认继续或开始新的选型才清除；从结果卡点「模型」「技术支持」跳出去看、15 分钟内回来（含点选型 tab）仍静默恢复不打扰；③ 此前「完全重新开始选型」的入口叫「全部分类」+ 收纳箱图标，用户看不懂，改为明确的「重新选型」+ 重来图标。全部为前端改动，无数据库迁移。

## 修复清单

### 1. 选型页误弹「产品数量不能超过 500」（v5.5.7 遗留）

- **现象**：用户没有点分享，选型结果一出现就弹出「产品数量不能超过 500」
- **根因**：结果出现后页面自动预创建「工单来源分享快照」，把当前匹配的全部产品 ID 冻结进快照；结果超 500 个产品被服务端拒绝，报错弹给了没在分享的用户
- **修复一**：匹配结果超 500 时自动改存**纯参数快照**——分享链接打开后回跳选型页按参数实时过滤（复用现成 selection-mode 机制），分享完整可用且产品列表永远最新
- **修复二**：后台预创建失败一律静默（有回退兜底）；用户主动分享的报错提示保留

### 2. 选型进度保存：自动恢复升级为问询横幅（核心重构）

- **主动进入（点选型菜单/侧栏/底部 tab）且上次有实质进度**：不再自动恢复——首页顶部横幅「继续上次未完成的选型？上次选到：XX 分类（已选 N 项）」，**[继续] [重新开始]** 两个按钮，恢复与否交还用户
- **永久草稿**：快照不再 2 小时过期——没确认就一直保存，直到用户点「继续」、开始新的选型（选分组/分类）或点「重新开始/首页」才清除
- **跳出去看静默恢复（15 分钟）**：从结果卡点「模型」「技术支持」跳出去、15 分钟内回到选型页（含点选型 tab 进入——移动端从模型页回来的主要路径）直接静默恢复到刚才的进度/结果，不多一次点击；看模型/图纸、提工单都在一刻钟内，超时则意图已模糊、回来问横幅
- **浏览器返回手势/刷新（2 小时内）**：静默恢复（体感是同一会话延续）
- **实现说明**：v5.5.7 的判定依赖 react-router 的 useNavigationType，实测在懒加载路由挂载时读到旧值（点 Link 进来也是 POP）导致提示不触发；本次改用 location.key 对比（POP 返回复用旧 key、PUSH 生成新 key）+ 文档导航时间 + 跳出标记三个原始信号，经 Playwright 端到端实测 23 项场景全部通过

### 3. 「重新选型」入口明确化

- 此前「完全重新开始选型」的入口是工具栏的「全部分类」按钮（功能正确：回选型首页 + 清空全部选择 + 清除草稿），但文案像导航链接、收纳箱图标无语义，用户看不懂
- PC 工具栏与移动端冻结头统一改为**「重新选型」+ 重来图标（restart_alt）**，点击回到选型首页并清除全部进度与草稿，两端行为一致
- 结果页原有「重新选择」保留（本分类内重选、回第一步），与「重新选型」（彻底重来回首页）语义互补

## 升级说明

- 无数据库迁移（schema 未变更）
- 服务器更新：`cd /opt/3dparthub && docker-compose pull && docker-compose up -d`，浏览器强刷一次（Cmd+Shift+R / Ctrl+Shift+R）；iOS 主屏 PWA 需彻底退出重开（等更新横幅或强杀）
- 上线后验收：
  - 选型选到有进度后去首页，再点选型菜单：出现「继续上次未完成的选型？」横幅；点「继续」回到进度、点「重新开始」全新开始
  - 选型到结果页点「技术支持」，在工单页点选型 tab 回来：直接回到刚才的结果（无横幅、无需点击）
  - 结果超 500 个产品的选型组合：不再弹「产品数量不能超过 500」
  - 工具栏出现「重新选型」按钮（↻ 图标），点击回到选型首页
