## 更新标题

3DPartHub v4.9.6 - 修复顶栏用户菜单 hover 失效（v4.9.5 回归）+ 修改密码改原地弹窗

## 标签描述

v4.9.6 is a hotfix for a v4.9.5 regression plus a UX improvement. The top-bar user menu stopped opening on mouse hover: v4.9.5 had gated hover intent behind the `(hover: hover) and (pointer: fine)` media query to fix touch-screen tap toggling, but that query reflects the device's _primary_ pointer capability — on touch-primary devices (touch laptops, tablet mode) it fails to match even when a real mouse is plugged in, killing hover entirely. Hover intent is now determined by event source instead: `onPointerEnter/onPointerLeave` with `e.pointerType === 'mouse'`, so a real mouse works on any device while touch taps (which dispatch `'touch'`) remain excluded — the original touch fix still holds. Additionally, the 修改密码 item in the user menu no longer navigates to the profile page and then pops the dialog (which read as a stutter): the password dialog was extracted into a shared component mounted through a React portal to document.body, so it opens in place, centered on the viewport, with no page change — the profile settings entry uses the same component. Frontend-only release, no database migration.

## 更新描述

本次为 **v4.9.5 回归修复 + 交互优化** 补丁，纯前端改动，无数据库迁移，前后端镜像均需更新。

**① 修复：鼠标悬停顶栏头像不再显示下拉菜单（v4.9.5 引入的回归）**

- 根因：v4.9.5 修触屏菜单「开了又立刻关上」时用 `(hover: hover)` 媒体查询门控悬停 —— 该查询反映的是设备**主指针**能力，触摸屏被报告为主指针的设备（触摸笔记本/平板模式）上即使插着真鼠标也不匹配，悬停被整个禁用
- 修复：改为按**事件来源**判断（`pointerenter` + `pointerType === 'mouse'`）—— 真鼠标在任何设备上都生效；触屏点击派发的是 `'touch'` 自动排除，原触屏修复依旧成立

**② 优化：用户菜单「修改密码」原地弹窗，不再跳页**

- 原行为：点击后先跳转个人设置页再弹窗，看起来像「卡了一下」
- 现行为：原地直接弹出修改密码弹窗，页面不切换、URL 不变
- 实现：`PasswordChangeDialog` 提取为共享组件，通过 React portal 挂载到 `document.body`（无论从哪个容器渲染都全屏居中，不受祖先包含块影响）；个人设置页的入口使用同一组件，行为一致

**③ 验证**

- E2E：桌面鼠标悬停开/移开关/再次开；菜单点「修改密码」原地弹窗（URL 不变、视口居中偏移 0/0）；移动端真实触摸（CDP）点头像菜单打开且不立即关闭、点菜单项弹底部面板；个人设置页弹窗回归正常
- 两端 `npm run verify`（TypeScript / ESLint / 测试 / UX 合同校验）全绿
