## 更新标题

3DPartHub v5.9.5 - gmsh 修复引擎安装方案重做（一键脚本入库 + 弹窗指引三行命令），本机端到端验证通过

## 更新描述

「修复预览（gmsh）」按钮的安装指引此前教的是一套在 alpine 容器上**跑不通**的方案：手写依赖清单漏库（libgomp/libxcb/libbz2）、glibc loader 启动方式在实测中段错误、挂载配置与实际不符。本版把安装方案整体重做并**在本机 QEMU 模拟的同源 alpine 容器里端到端验证**（真实业务 STEP 文件走 server 同款参数：OCC 读入 + 网格化，53,617 节点 / 108,140 单元产物）后发布。仅前端文案与部署脚本变更，无服务端代码与数据库变更。

## 变更清单

### 1. 一键安装脚本入库 `deploy/install-gmsh.sh`（本版核心）

- **依赖收集自动化**：用 readelf 递归解析 ELF NEEDED 闭包收集依赖库（手写清单必漏——实测连漏 libgomp/libxcb/libbz2）
- **loader 挂载方案**：glibc loader 单文件挂载到容器 `/lib64/ld-linux-x86-64.so.2`（内核 PT_INTERP 正常启动；显式 `ld.so 程序` 调用实测段错误，不可用）
- wrapper 只做 `LD_LIBRARY_PATH` 注入；compose 挂载五条（bin/real/sdk/deps + loader），插入带幂等判断 + 备份 + `docker-compose config` 校验失败自动回滚
- 幂等可重跑；支持 `GMSH_VER=x.y.z` 升级指定版本
- 已在 QEMU 模拟 x86_64 alpine 容器（与 api 镜像同源）端到端验证：`gmsh -version` OK + 真实业务 STEP（Circle/BSpline 几何，主引擎 BRepMesh 丢面同类）完整网格化

### 2. 管理后台「修复预览」弹窗指引重写

- 旧指引（两段手写命令，依赖清单缺库 + 挂载方案过时）→ 新指引三行命令：从仓库 raw 地址下载 `deploy/install-gmsh.sh` 并执行
- 五语言同步（zh/en/ja/ko/de）

### 3. CLAUDE.md 新增「服务器 gmsh 兜底引擎」运维节

方案要点、三行安装命令、日常用法（自检/升级）、成功标志、失败下限说明（gmsh 探测不到自动跳过走主引擎，不影响网站现有功能）。

## 升级说明

- 无数据库迁移
- 服务器更新（标准自动流程）：
  ```bash
  cd /opt/3dparthub
  docker-compose pull
  docker-compose up -d
  ```
  更新后强制刷新浏览器（Cmd+Shift+R / Ctrl+Shift+R）
- **安装 gmsh（可选，装完「修复预览」按钮亮起）**：管理后台任意模型 → 编辑 → 点「修复转换」旁的感叹号，弹窗内两步命令复制到服务器执行即可（或直接）：
  ```bash
  curl -fsSL https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/deploy/install-gmsh.sh \
    -o /opt/3dparthub/install-gmsh.sh && chmod +x /opt/3dparthub/install-gmsh.sh
  bash /opt/3dparthub/install-gmsh.sh
  ```
  服务器之前若按旧指引手工装过 gmsh：重跑本脚本会自动修正依赖闭包与挂载配置（幂等，旧的错误挂载需按脚本第 5 步提示或手工核对一次）。
- 上线后验收：未装 gmsh 时网站一切如常（按钮灰置）；装完后 `docker exec 3dparthub-api /usr/local/host-bin/gmsh -version` 输出 `4.13.1`、按钮亮起可转。
