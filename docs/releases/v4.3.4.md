## 更新标题

3DPartHub v4.3.4 - 批量上传「零件目录优先，子文件夹变体跳过」+ 中文 ZIP 乱码修复（EFS 位）+ 备份加密完成弹窗

## 标签描述

3DPartHub v4.3.4 hardens batch archive upload and backup UX based on real-world NAS part-library uploads. New selection rule "part dir wins": when a part directory contains a direct STEP file, model files in its subfolders (historical revisions like 2023-11-24更新/, accessory combos like 含喷嘴/) are now skipped automatically instead of being uploaded as separate models — previously each variant became a duplicate-looking model the admin had to delete by hand (99 manual deletions in one batch). Skipped entries return status "skipped" in the upload report and the modal shows "X 成功，Y 跳过". If a part dir has NO direct file, subfolder files remain the only source and all are kept (no regression). Fixes mojibake for UTF-8 Chinese ZIPs: Python/macOS-created archives set the ZIP EFS flag (bit 11) but the decode heuristic scored GBK mojibake HIGHER (each UTF-8 3-byte CJK char decodes into 1.5 GBK mojibake chars, inflating the CJK score), so 204 models once landed in a garbage category; the EFS flag is now trusted first. Backup encryption UX: after an encrypted backup completes, a one-time dialog explains key custody (losing BACKUP_ENCRYPTION_SECRET means the archive is unrecoverable), the backup list shows an "已加密" badge, and the progress API exposes an encrypted flag. Model detail page: displayed download filename now lowercases the extension (.STEP → .step) to match the actual download. 23 new unit tests (17 archivePath incl. nesting matrix + EFS, 6 selectBatchModelEntries skip-rule). No DB migration.

## 更新描述

本次为**批量上传与备份体验更新**，无数据库迁移，共四项改动。

**一、批量上传新增「零件目录优先，子文件夹变体跳过」规则**

- 场景：NAS 零件库的零件目录里常有子文件夹——历史改版（`2026-2-26改支架/`）、加配件组合（`含喷嘴/KTHP+JCW.STEP`）。此前它们会被当成独立模型上传，和本体混在一起，只能事后手工删
- 现在：**零件目录自己有直接 STEP 时，子文件夹里的模型文件自动跳过不传**。上传报告里逐条标注「已跳过」，弹窗汇总显示「X 成功，Y 跳过」
- 零件目录**没有**直接 STEP 时（子文件夹是唯一来源），行为不变：全部保留
- ZIP / RAR 通道、单零件压缩包模式均生效；子文件夹里的 PDF 图纸仍按原逻辑挂到零件目录本体模型

**二、修复中文 ZIP 乱码（EFS 标志位）**

- 场景：用 Python / macOS 打的中文文件名 ZIP（规范会设置 EFS/UTF-8 标志位），此前的解码启发式会把正确的 UTF-8 名错判成 GBK 乱码（乱码串的"汉字计数"反而更高），导致整批模型进乱码分类
- 现在：检测到 EFS 标志位直接信任 UTF-8 解码；无标志位的 ZIP（Windows 中文系统常见）仍走 GBK/UTF-8 智能识别，行为不变

**三、备份加密完成弹窗 + 列表「已加密」标记**

- 开启备份加密后，备份完成时弹一次提醒：备份包已加密、密钥在哪个环境变量、**密钥丢失将永久无法恢复**
- 备份列表中加密备份显示 🔒「已加密」标记，一眼区分明文/加密包

**四、模型详情下载文件名后缀小写**

- 详情页展示的文件名与实际下载名对齐：`.STEP/.STP` 等大写后缀统一显示为小写（原文件名原样保存，仅展示层变化）

**建议升级后验证**：管理后台 → 模型 → 批量上传一个含「子文件夹变体」的 ZIP，弹窗应显示跳过数；若开启备份加密，新建备份完成后应弹出密钥保管提醒。
