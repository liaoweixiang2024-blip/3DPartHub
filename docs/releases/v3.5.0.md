## 更新标题

3DPartHub v3.5.0 - 新增邀请码注册功能（一次性邀请码 + 按用户授权生成）

## 标签描述

3DPartHub v3.5.0 minor release — adds an invite-code registration feature. Admins can grant individual users the "can generate invite codes" permission (a per-user `canInvite` flag, no role/group system); those users generate one-time invite codes or invite links (`/register?invite=<code>`) from a new "My Invites" page. New users must fill a valid code to register when the single "Invite-code registration" toggle is on; off = fully open registration (zero behavior change). Each code is single-use (status + unique `usedById`, claimed atomically inside the registration transaction so concurrent registrations on the same code can never both succeed), supports optional expiry, and can be revoked while unused. Default off. Includes a DB migration (`add_invite_codes`: adds `users.can_invite` + new `invite_codes` table). Backend: new `/api/invites` router (create/list/revoke) gated by `featureGuard('require_invite_code')`, registration endpoint validates + atomically consumes the code, admin user management + profile/login/register responses carry `canInvite`. Frontend: new MyInvitesPage, register form reads `?invite=` to auto-fill, user-management checkbox, settings toggle, TopNav entry, route-level FeatureGate guard. Single consolidated toggle (the earlier two-toggle design was simplified to one). No data loss; existing users default to `canInvite=false`.

## 更新描述

- **新增「邀请码注册」功能**：后台「设置 → 功能开关」新增「邀请码注册」开关（默认关闭，关闭时行为与旧版完全一致）。开启后：
  - 管理员在「用户管理 → 编辑用户」勾选「可生成邀请码」，授予该用户生成邀请码的权限（按单个用户授权，不依赖角色或用户组）。
  - 被授权用户在顶部菜单的「我的邀请码」页面，可生成**一次性邀请码 / 邀请链接**（`${站点地址}/register?invite=<码>`），支持一键复制码或链接、可选设置过期时间、对未使用的码可吊销。
  - 新用户注册时**必须填写有效邀请码**才能完成注册；打开邀请链接会自动切换到注册模式并预填邀请码。
- **一次一码，防并发滥用**：每个邀请码仅供一人注册，用完即失效；注册时在数据库事务内原子地抢占并标记已用，即使同一码被两人同时使用，也只有先到的能成功，后到的会收到「邀请码已被使用」。无效、过期、已吊销的码都会被明确拒绝。
- **设计简化为一个开关**：早期设计有「功能总开关 + 是否强制」两个开关，已合并为单个「邀请码注册」开关——关闭=完全开放注册（无邀请码入口、生成码接口返回 403），开启=必须填码注册。逻辑直观，无冗余组合。
- **数据库变更（需迁移）**：新增 `invite_codes` 表（码、状态、创建人、使用人、过期时间等），并在 `users` 表增加 `can_invite` 字段（默认 false，现有用户全部不受影响）。迁移文件 `20260731085916_add_invite_codes` 随镜像发布，部署时自动应用，无任何删表 / 丢数据操作。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## 部署备注

本次改动**包含数据库迁移**（`server/prisma/migrations/20260731085916_add_invite_codes/`：`users` 加 `can_invite` 列默认 false + 新建 `invite_codes` 表），属增量变更，**无删表 / 无丢数据**。镜像内已含迁移文件，api 容器启动时会自动 `prisma migrate deploy` 应用。

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.5.0 api / web 镜像
docker-compose up -d              # 重建容器（api 启动自动跑迁移；保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health
curl -s http://localhost:3780/api/settings/version   # 应显示 v3.5.0
```

启用步骤：管理员登录 →「设置 → 功能开关」开启「邀请码注册」→ 在「用户管理」给指定用户勾选「可生成邀请码」→ 该用户即可在「我的邀请码」生成码 / 链接分享。默认关闭，不开启则与旧版完全一致。

注意：少数用户的浏览器若缓存了**旧版本的自建 bundle**，还可能遇到 CSP `connect-src 'self'` 报错；这类情况清一次站点数据（含旧 Service Worker）再硬刷新即可。
