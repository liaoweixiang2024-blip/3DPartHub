# v5.4.9

发布日期：2026-10-09

## 更新标题

3DPartHub v5.4.9 - 首屏体积优化（505KB → 395KB，-22%）：翻译字典按语言懒加载 + 分包去钉包 + JSZip 移出首屏

## 更新描述

本次为**首屏加载性能优化**，三项改动合计把首次访问的首屏下载量从 505KB 压缩到 395KB（gzip 实测，-110KB / -22%）：六种语言的翻译字典从「全量静态打进入口」改为「默认中文内联、其余按语言动态加载」；移除把整个目录/组件钉进单一 chunk 的分包规则（钉包使 manual chunk 吸收共享模块 blob 整体落入首屏，且改一个文件全员重下大块）；把只有懒加载上传弹窗使用的 JSZip 从 eager vendor 桶排除。功能行为零变化（无头浏览器四场景实测通过），无数据库迁移、后端代码零改动（api 镜像仅版本号随动），更新 web 镜像即生效。

## 改动清单

### 1. 翻译字典按语言懒加载（-90KB 首屏）

- **问题**：`initI18n` 静态引入全部六种语言资源（zh 全量 + en 全量 + 繁中/日/韩/德覆盖片段，合计约 90KB gzip），入口闭包绕不开，所有访客首屏全量下载
- **修复**：默认语言 zh-CN 保持同步内联（绝大多数访客零额外请求）；en-US 与 ja-JP/ko-KR/de-DE/zh-TW 覆盖片段拆成独立模块按需 `import()`，每个语言一个异步 chunk，en-US 作为日/韩/德的合并基底由 Rollup 自动去重共享；运行时切语言走 `ensureLocaleLoaded`（addResourceBundle 注入后再 changeLanguage）
- 合并逻辑与原实现逐字对齐（嵌套结构与基底完全一致），`overrides.ts` 按语言机械拆分为 `overrides/{ja-JP,ko-KR,de-DE,zh-TW}.ts`

### 2. 分包去钉包（-20KB 首屏 + 发版缓存粒度改善）

- **问题**：manualChunks 把 `src/api/**`+`src/stores/**` 钉成 app-api（178KB）、`src/components/shared/**`+hooks+lib 钉成 app-shared（183KB）、UploadModal/NotificationPanel/MobileNavDrawer 各钉一块——入口引用其中任意模块，整块成为首屏依赖；且改任意一个文件 → 大块哈希失效 → 所有用户重下
- **修复**：全部改为 Rollup 自然分包（页面专属代码跟随各自懒路由，多页共用模块自动生成共享小 chunk，模块级去重不重复打包）；UX 合同同步升级——钉包规则回归即 CI 失败

### 3. JSZip 移出首屏 vendor 桶（-40KB 首屏）

- **问题**：JSZip 只被懒加载的上传弹窗使用，但默认 vendor 桶是单一 chunk、被入口闭包整体拖成 eager，JSZip 搭车进首屏
- **修复**：加入 xlsx/Sentry 同款「跟随自然依赖图」排除清单，落到懒加载 chunk

## 验证

- 首屏 eager 集合实测（gzip）：505KB → 395KB；五语言 chunk、three.js 查看器 chunk 确认全部懒加载
- 无头浏览器（CDP）四场景：zh 默认渲染中文且零语言包网络请求；en-US 渲染英文、精确拉取 1 个语言 chunk；ja-JP 渲染日文、拉取 en 基底+ja 覆盖 2 个 chunk；切回 zh 不再发请求（缓存复用）
- client `npm run verify` 全绿（四项合同含新增的「禁止钉包回归」「字典必须动态加载」断言 + 33 单测）；server 无代码改动 verify 全绿；仓库根 `npm run verify:deploy` 全绿

## 升级说明

- 无数据库迁移（schema 未变更）
- 服务器更新：`cd /opt/3dparthub && docker-compose pull && docker-compose up -d`，浏览器强刷一次
- 本次仅 web 镜像有实质改动，api 镜像仅版本号随动，两端一并拉取即可
- 上线后验收：DevTools Network 看首页首次加载，`/assets/` 的 JS 合计传输量应明显小于此前；非中文用户首次访问会多 1-2 个小语言包请求（属预期）
