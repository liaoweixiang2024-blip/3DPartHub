# v5.5.0

发布日期：2026-10-09

## 更新标题

3DPartHub v5.5.0 - 修复多次强刷后被登出（refresh 轮换宽限自愈）+ web-vitals 上报节流 + 字体预加载告警消除

## 更新描述

本次修复一个**真实用户可遇的登出 bug**：多次强制刷新后账号被登出（`/api/auth/refresh 401 → 会话已失效`）。根因是刷新令牌轮换在响应被强刷掐断时丢失新 cookie，浏览器 cookie 罐卡死在已用令牌上，宽限期一过即被按「疑似泄露」吊销全部会话。附带两个控制台体验修复：web-vitals 上报节流（连续强刷不再 429 刷屏）、字体预加载移除（「preloaded but not used」告警消除）。含一处后端行为变更，无数据库迁移。

## 修复清单

### 1. 多次强刷后被登出（核心修复）

- **现象**：多次强制刷新后 `POST /api/auth/refresh 401`，控制台报「会话已失效，请重新登录」，账号被登出
- **根因链**：每次页面加载都会轮换刷新令牌（旧 cookie 作废、Set-Cookie 发新 cookie）。强刷会把在途响应掐断——服务端已把旧令牌标记「已用」，新 cookie 却没进浏览器 → cookie 罐卡死在已用令牌上。原宽限分支（30 秒内重放）只发 accessToken **不换新 cookie**，罐子无法自愈；30 秒一过，下一次刷新被判定「宽限外重放 = 疑似泄露」→ 吊销该用户全部会话
- **修复**（双管齐下）：
  1. 宽限分支同样换发新 refresh cookie——每次宽限命中都把卡死的罐子救活（本地实测完整链路：掐断 Set-Cookie → 宽限重放拿到新 cookie → 新链持续 200 正常轮换）
  2. 宽限窗口 30s → 120s，覆盖「强刷一次 → 隔一分钟再回来」的真实节奏；窗口外重放仍按疑似泄露吊销（防窃取语义不变）

### 2. web-vitals 上报节流（429 消除）

- **现象**：连续强刷时 `POST /api/health/web-vitals 429` 刷屏（每次加载触发 5 个指标上报，撞上 60 次/分钟限流）
- **修复**：会话内每个指标 5 分钟最多上报一次（sessionStorage 记录），采样价值不变、噪声与服务端日志灌水一并消除；隐私模式 sessionStorage 不可用时照常上报（限流兜底）

### 3. 字体预加载移除（「preloaded but not used」告警消除）

- **现象**：控制台持续提示字体 `preloaded but not used`
- **根因**：预加载与 CSS 的 @font-face URL 完全一致（非失效），但站点开启登录门槛后未登录首屏是纯中文锁定页，首屏根本没有使用拉丁标题字体的文本——预加载白拿 26KB 且触发 Chrome 告警
- **修复**：移除两个字体的 link preload，@font-face 在主 CSS 中按需拉取（font-display: swap 不挡渲染）；UX 合同同步改为「禁止字体 link preload」防回归
