## 更新标题

3DPartHub v3.9.9 - 备份可靠性加固：自动备份补跑 + 失败告警 + 恢复后缓存彻底清理

## 标签描述

3DPartHub v3.9.9 is a backup-reliability hardening release with no DB migration and frontend-only version bump (no client changes). The automatic backup scheduler becomes catch-up style: once the scheduled time has passed and no backup has run today, it triggers — a server restart or a blocked scheduler tick around the scheduled time no longer silently skips that day's backup (backup_last_auto_date idempotency still prevents duplicates). Failed scheduled backups (full and module scopes) now send an in-app notification to all admins with a 6-hour cooldown, so failures surface immediately instead of hiding in the backup settings page. After a restore completes, the worker now broadcasts a settings-cache invalidation over Redis pub/sub (all master-process workers refresh instantly instead of waiting out the 30s TTL) and clears the auth:user:\* cache prefix (tokens of users removed by the restore are rejected immediately instead of within 60s). The \_safety_snapshots/ directory is now cleaned on startup per the documented 7-day retention: snapshots not referenced by any restore-in-progress marker and older than 7 days are removed, while marker-referenced snapshots (the only rollback credentials for hard-interrupted restores) are always kept.

## 更新描述

本次为备份/恢复可靠性加固，**无数据库迁移，无前端改动**（前端仅版本号随发）。

背景：对备份恢复全链路（6000 行 backup.ts）做了完整性审计，确认全量备份覆盖全部 31 张数据表与全部业务文件目录、全量恢复完整重建、模块恢复 TRUNCATE CASCADE 无连带误伤、失败自动回滚与硬中断快照保护机制完备。本次修复审计发现的 4 个可靠性短板：

- **[备份] 自动备份改为补跑式调度**
  - 原实现只在计划时刻后的 120 秒窗口内触发：服务器恰好在窗口期重启（如定时备份时刻前后部署更新）或调度 tick 被阻塞超过 2 分钟，当天自动备份会被静默跳过，连续多天无人察觉。
  - 现改为「计划时刻已过且今天还没跑过即触发」；backup_last_auto_date 幂等保护不变，不会重复执行。
- **[备份] 自动备份失败即时告警**
  - 失败状态原来只写在后台备份页，管理员不主动看就永远不知道。
  - 现在自动备份失败（全量/模块）会给全体管理员发站内通知（通知类型「备份」，6 小时冷却防重复轰炸；手动备份失败不发——用户就在界面上看得到）。
- **[恢复] 恢复后缓存彻底清理**
  - 设置内存缓存：恢复 worker 现通过 Redis pub/sub 广播失效，所有主进程立即刷新（原来要等 30 秒 TTL，恢复后头 30 秒可能读到旧配置）。
  - 认证缓存：新增清理 auth:user:\* 前缀——恢复覆盖数据库后，已不存在用户的旧 token 立即失效（原来最长 60 秒内仍可通过认证）。
- **[维护] 安全快照目录按文档保留 7 天**
  - \_safety_snapshots/ 启动时清理超过 7 天的孤儿快照（硬中断残留），避免无限膨胀；仍被恢复中断 marker 引用的快照一律保留（那是唯一的回滚凭据）。

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**无数据库迁移，无前端功能改动**。升级步骤：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.9.9 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v3.9.9
```

升级后注意：

- 自动备份补跑在**容器重启后立即生效**：若重启时已过当天的计划备份时刻且当天未备份，启动后约 1 分钟内会自动补跑一次。
- 建议保留现有的每日自动备份策略；如尚未开启自动备份，可在后台「备份」页开启（默认凌晨 03:00）。
- 升级后首个自动备份周期内如遇失败，管理员会收到站内通知（通知类型「备份」）。

默认跟随 latest 的部署由 Watchtower 自动更新。
