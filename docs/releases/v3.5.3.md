## 更新标题

3DPartHub v3.5.3 - 安全与数据丢失风险修复（JWT 强制 / 删用户级联预检 / 附件白名单 / SSRF 加固 等）

## 标签描述

3DPartHub v3.5.3 is a **security and data-loss hardening patch**. No DB migration, no feature change — focused entirely on closing risks found in a source-code audit.

**Breaking (deployment):** `JWT_SECRET` is now **required**. The docker-compose default fallback was removed (`:?` — missing value refuses to start), and the server now hard-fails on any known weak/public JWT secret in production (previously only warned). **Before deploying, ensure your `.env` has a strong `JWT_SECRET` (e.g. `openssl rand -hex 32`).** If it already does, zero impact.

Security fixes:

1. **[Critical] JWT weak default → full takeover**: docker-compose no longer ships a fallback JWT secret; `config.ts` hard-fails on known weak secrets in production (was warn-only). Previously an operator who forgot to set `JWT_SECRET` would run with the public repo default, letting anyone forge an `ADMIN` token.
2. **[High] Delete-user cascade wiped the whole model library**: deleting a user now pre-checks their models/versions and refuses (400) with a clear "reassign or delete those models first" message — previously `user.delete()` cascaded across 6 tables (models, versions, favorites, downloads, comments, shares), irreversibly.
3. **[Medium] Ticket/inquiry attachments accepted any extension**: `fileFilter` now enforces the `ticketAttachmentExts` allowlist (images by default); `.html/.svg/.exe` etc. are rejected. The allowlist already existed in config but was unused on the upload path.
4. **[Medium] Protected downloads missing `X-Content-Type-Options: nosniff` + unsafe inline**: `sendAcceleratedFile` now always sets `nosniff`, and any non-allowlisted content type (`.html/.svg/.htm`…) is forced to `Content-Disposition: attachment` so browsers download instead of render.
5. **[Medium] Share creation lacked model ownership check**: any logged-in user could create share links for any model. Now requires `model.createdById === userId` (or ADMIN).
6. **[Medium] Email verification code had no IP rate limit**: added `emailCodeLimiter` (30/hour/IP) to `POST /api/auth/email-code` — prevents multi-email + captcha-pool SMTP bombing. Orthogonal to the existing per-email cooldown.
7. **[Medium] SVG on cloud storage path lacked CSP**: `cloudFirstStatic` now sets the same strict CSP + `nosniff` for `.svg` as the local `express.static` path did, blocking inline script execution from uploaded SVGs.
8. **[Low] Login lockout was email-only**: added an IP-dimension failure counter (20/15min) alongside the email counter — mitigates cross-account credential stuffing and targeted lockout harassment.
9. **[Low] SSRF DNS rebinding (TOCTOU)**: new `lib/remoteImageFetch.ts` resolves once, validates all addresses against private/reserved ranges, then **connects directly to the validated IP** (no second DNS lookup during fetch) — closes the rebinding window in product-wall / option-image remote-URL fetches. Redirects are rejected.
10. **[Low] `removeExistingFiles` lacked path containment**: now only deletes files under `static/` or `uploads/` — defense-in-depth against any future route writing user input into a file-path field.

Data-loss UX: deleting a selection category that still contains products now returns 409 with the product count; the admin UI shows a confirm dialog ("will also delete N products") before the destructive delete.

Verified: server 142 unit tests green, client build + 12 tests green. No DB schema change, fully backward compatible except the JWT requirement above.

## 更新描述

本次是**安全与数据丢失风险修复版本**，不含功能变更、不含数据库迁移，仅修补源码审计发现的风险点。

- **⚠️ 部署前必读（唯一的破坏性变更）**：`JWT_SECRET` 现在改为**强制要求**。docker-compose 不再提供兜底默认值（未在 `.env` 设置将拒绝启动），服务端在生产环境若发现 `JWT_SECRET` 是已知的弱值/公开默认值会直接退出（之前只告警）。**部署前请确认 `.env` 的 `JWT_SECRET` 已是强随机值**（如 `openssl rand -hex 32`）。若已设置，则无任何影响。
- **[严重] 修复 JWT 弱密钥可全站接管**：此前若运维忘记设置 `JWT_SECRET`，容器会用仓库里公开的兜底密钥启动，任何人都能据此自签管理员令牌接管站点。现已强制要求强密钥。
- **[高] 修复删除用户会清空整个模型库**：此前删除一个用户会因其模型级联删除（onDelete:Cascade）连带硬删该用户的全部模型、模型版本、收藏、下载记录、评论、分享链接（跨 6 张表，不可逆，无回收站）。现在删除前会预检该用户名下的模型/版本，若有则拒绝并提示「请先在模型管理转移归属或删除这些模型」。
- **[中] 工单/询价附件限制扩展名白名单**：此前附件上传只检查「有没有扩展名」，`.html/.svg/.exe` 等任意类型都能上传。现已强制使用后台配置的扩展名白名单（默认仅图片）。
- **[中] 受保护下载补 `nosniff` + 危险类型强制下载**：所有受保护下载/附件响应现在都带 `X-Content-Type-Options: nosniff`，且非白名单类型（如 `.html/.svg`）一律强制「下载」而非浏览器内联渲染，杜绝存储型 XSS 的渲染路径。
- **[中] 修复分享越权**：此前任意登录用户都能为任意模型创建分享链接（绕过站内下载配额、代管他人模型）。现仅模型所有者或管理员可创建。
- **[中] 邮箱验证码加 IP 级限流**：发送验证码接口新增按 IP 限流（默认 30 次/小时），防多邮箱 + 验证码池轰炸、消耗邮件服务配额。与既有的单邮箱冷却互为补充。
- **[中] SVG 云存储路径补 CSP**：配了云存储时，SVG 直链访问原本缺内容安全策略，可被内嵌脚本利用。现与本地路径保持一致的严格 CSP。
- **[中] 删除选型分类改为二次确认**：分类下还有产品时，后端返回产品数量并拒绝静默删除，前端弹出「将连带删除 N 个产品」的强制确认框，确认后才真正删除。
- **[低] 登录失败增加 IP 维度计数**：在原有按邮箱锁定的基础上，新增按 IP 的失败计数（20 次/15 分钟），缓解跨账号撞库与「用受害者邮箱错密码触发锁定」的定向骚扰。
- **[低] 修复远程图片拉取的 SSRF DNS rebinding**：产品墙/选型图片的「远程 URL 拉取」原先先校验 DNS 解析、再下载（两步之间有被 DNS 切到内网的时间窗）。现统一为「校验后直连已校验的 IP」，消除该窗口，并拒绝重定向。
- **[低] 文件删除加目录包含性校验**：作为纵深防御，删除文件操作现在只允许在 `static/` 与 `uploads/` 目录内进行。

前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## 部署备注

⚠️ **本次唯一的破坏性变更**：`JWT_SECRET` 现为强制。**部署前必须确认服务器 `/opt/3dparthub/.env`（或对应部署目录）的 `JWT_SECRET` 已是强随机值**：

```bash
# 在服务器确认 / 设置（若尚未设置或仍是默认值）
JWT_SECRET="$(openssl rand -hex 32)"  # 写入 .env
```

确认后即可正常升级（保留数据卷，绝不用 `down -v`）：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.5.3 api / web 镜像
docker-compose up -d              # 重建 api / web 容器
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health
curl -s http://localhost:3780/api/settings/version   # 应显示 v3.5.3
```

若 `JWT_SECRET` 未设置或仍是弱值，api 容器会启动失败并在日志中提示设置强密钥——这是有意为之的安全行为，按提示设置后重启即可。

本次改动**不涉及数据库迁移**，是镜像内的代码与前端资源变更。默认跟随 latest 的部署由 Watchtower 自动更新。
