## 更新标题

3DPartHub v4.1.1 - 修复分类访问限制不回显 + 列表直观看受限状态（徽章与继承标记）

## 标签描述

3DPartHub v4.1.1 fixes the v4.1.0 category access-control edit round-trip and makes restriction status visible at a glance. Root cause: the admin category page reads the public category-tree API, whose node shape never included the new access fields — so saves did persist to the database but reopening the dialog always showed the switch off. The tree API now returns restricted on every node, and additionally returns allowedRoles/allowedUserIds to ADMIN only (the admin's cache bucket is always empty, so no cache mixing; non-admin users get just the boolean flag, never the whitelist). The category list now shows a 受限 badge directly on each restricted row, children under a restricted parent show a lighter 受限（继承） badge (restrictions propagate down the subtree even when the child's own switch is off), and the edit dialog warns when an ancestor is restricted (the child's own switch alone cannot lift it). No DB migration.

## 更新描述

本次为 **v4.1.0 分类访问权限的补丁修复**，无数据库迁移。

**修复：访问限制保存后重新打开显示关闭**

- 根因：分类管理页读的是公开分类树接口，该接口的节点结构里没有权限字段——保存其实**已写进数据库**（拦截是生效的），只是弹窗回显时拿不到字段
- 修复：分类树接口现在每个节点都返回 `restricted` 标记；**管理员**额外拿到 `allowedRoles`/`allowedUserIds` 白名单用于弹窗回显（管理员缓存桶恒为空、无缓存混杂；普通用户只拿布尔标记，不泄露白名单内容）

**增强：列表直观看清受限状态（不用点进弹窗）**

- 列表行直接显示 **受限** 徽章（红底锁图标）
- 受限分类下的子分类显示浅色 **受限（继承）** 徽章——父分类受限时限制沿子树生效，子分类自身开关即使没开也被限制
- 编辑弹窗：当上级分类已受限时显示提示「限制沿子树向下生效，如需单独放开请先关闭上级分类的限制」，避免误以为子分类开关能覆盖父级限制

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**无数据库迁移**。升级步骤：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v4.1.1 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v4.1.1
```

升级后注意：

- v4.1.0 保存的受限分类**拦截一直是生效的**（数据都在库里），本版只是让后台能正确回显和直观查看
- 分类树有 10 分钟缓存：升级后如弹窗仍显示旧状态，等缓存过期或再次保存任意分类即可刷新

默认跟随 latest 的部署由 Watchtower 自动更新。
