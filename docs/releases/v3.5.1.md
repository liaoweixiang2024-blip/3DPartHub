## 更新标题

3DPartHub v3.5.1 - 修复注册弹窗缺失邀请码输入框（v3.5.0 遗漏）

## 标签描述

3DPartHub v3.5.1 patch release. Fixes the invite-code field missing from the registration modal (AuthModal). v3.5.0 added the invite-code registration feature but only wired the invite-code input into the standalone LoginPage (/login, /register); the AuthModal component — the popup shown when users click "Register" from anywhere in the app — has its own independent registration form that was missed, so the invite-code input never appeared there even with the toggle on and require_invite_code=true returned by the API. This release adds the same invite-code logic to AuthModal: a new inviteCode field in FormErrors, the input rendered in register mode when featureFlags.invite is true, required-field validation, and the field passed to authApi.register. Both registration entry points (LoginPage and AuthModal) now behave consistently. Frontend-only fix; no backend change, no DB migration. The API image is republished unchanged from v3.5.0 for version alignment; the Web image is the actual fix.

## 更新描述

- **修复注册弹窗缺失邀请码输入框**：v3.5.0 新增「邀请码注册」功能时，只给独立的登录/注册页（LoginPage，即 `/login`、`/register`）接上了邀请码输入框，遗漏了 `AuthModal`——也就是用户在站点内任意位置点「注册」时弹出的那个弹窗。`AuthModal` 是一份独立的注册表单，有自己的一套字段与提交逻辑，所以即便后台已开启「邀请码注册」、前端也确实拿到了 `require_invite_code=true`，弹窗里始终不会出现邀请码输入框，表现为「开了开关却看不到填邀请码的地方」。本次给 `AuthModal` 补齐了与 `LoginPage` 完全一致的邀请码逻辑：注册模式下且邀请码功能开启时渲染输入框、提交前校验必填、注册请求带上邀请码。修复后两个注册入口（页面与弹窗）行为一致。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## 部署备注

本次改动**不涉及数据库迁移 / docker-compose**，是**纯前端修复**（只需更新 web 镜像；api 镜像跟随发版一并打 v3.5.1 标签，内容与 v3.5.0 一致）。默认跟随 latest 的部署由 Watchtower 自动更新；需要立即更新时执行：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.5.1 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health
curl -s http://localhost:3780/api/settings/version   # 应显示 v3.5.1
```

升级后开启「设置 → 功能开关 → 邀请码注册」，在站点内任意位置点「注册」弹出注册弹窗，即可看到「邀请码」输入框（开关开启时必填）。
