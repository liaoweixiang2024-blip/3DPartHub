# v5.5.1

发布日期：2026-10-09

## 更新标题

3DPartHub v5.5.1 - 无痕/未登录访客控制台净化（auth/refresh 无 cookie 探测改 204 + 客户端无会话短路）

## 更新描述

修复无痕窗口/未登录访客每次页面加载控制台出现的 `POST /api/auth/refresh 400（缺少 refresh token）`。客户端启动时总是探测式调用会话恢复端点，无登录凭据的访客本就没有 cookie——这是常态而非错误请求，回 400 会在每个匿名页面加载的控制台打出失败请求行。经生产环境系统性抓取（匿名视角、五个页面、全部 ≥400 请求），这是**唯一**的匿名噪声源，本版一并清除。两端均有改动，无数据库迁移。

## 修复清单

### 1. 服务端：无 cookie 的 refresh 探测回 204

`POST /api/auth/refresh` 在没有 refresh cookie 时改回 `204 No Content`（原来 400 + 错误体）。无会话不是错误语义；2xx 响应浏览器不会在控制台打印失败行。

### 2. 客户端：无会话短路，不再拉 profile

`doRefresh` 拿不到 accessToken（204 无体）时直接按「无会话」收尾返回，不再继续请求 `/api/auth/profile`（那会再制造一个 401 控制台噪声）。正常登录/轮换路径行为不变（本地实测：无 cookie → 204；有 cookie → 200 正常轮换）。

## 验证

- 生产环境匿名视角系统性抓取（CDP Network 域，`/`、`/models`、`/selections`、`/downloads` 五次加载的全部 ≥400 请求）：仅 `auth/refresh`（公开页 1 次、受保护页 2 次/加载），无其他噪声端点——本版全部静默化
- server `npm run verify` 全绿（192 测试）；client `npm run verify` 全绿（33 测试）；仓库根 `npm run verify:deploy` 全绿
