## 更新标题

3DPartHub v3.5.2 - 邀请码功能完善（上限 + 后台总览）+ 注册地址省市区联动 + 多项体验优化

## 标签描述

3DPartHub v3.5.2 minor release. Builds on the v3.5.0 invite-code feature and v3.5.1 registration-modal fix with a batch of refinements:

1. **Invite-code admin overview page** (admin menu "邀请管理"): lists all codes with creator, status, invitee (who invited whom, which code), expiry, and active/used/revoked stats — backed by new `GET /api/admin/invites`.
2. **Per-user active invite-code cap** (`invite_max_active_per_user` setting, default 10, 0=unlimited): enforced at generation; front-end shows "待使用 X / N" and disables the generate button at the limit.
3. **Registration address → China province/city/district cascading dropdown + detailed-address input** (new `RegionSelect` component, data from `@vant/area-data`); stored as a concatenated string (zero backend change, backward compatible with existing free-text addresses).
4. **Phone/company placeholders neutralized** — no longer mention inquiry/delivery purpose.
5. **Invite-code dropdown selection lag fixed** — address moved to a ref so selecting province/city/district no longer re-renders the whole registration form.
6. **canInvite reflects immediately** after an admin toggles it for the currently-logged-in user (no re-login needed to see the "My Invites" entry).
7. **"My Invites" menu icon** added (card_giftcard → Gift via lucide).
8. **Admin nav auto-merges new DEFAULT_NAV items** so legacy sites that saved a custom `nav_items` still see new admin pages, in their designed position (not pushed to the end).
9. **Menu label** "邀请码管理"(5 chars) → "邀请管理"(4 chars) for alignment, repositioned above System Settings.

New frontend dependency: `@vant/area-data`. No DB migration.

## 更新描述

- **邀请码管理后台页**：管理员后台新增「邀请管理」页（admin 菜单），集中查看所有邀请码——每条显示邀请码、邀请人（谁创建的）、状态（待使用/已使用/已吊销）、被邀请人（注册的新用户）、过期与创建时间；顶部有「待使用 / 已使用 / 已吊销」统计。便于审计「谁邀请了谁、用的什么码」。后端新增 `GET /api/admin/invites`。
- **邀请码待使用上限**：为防止滥用，新增设置项「邀请码待使用上限」（`invite_max_active_per_user`，默认 10，0 表示不限）。被授权用户生成邀请码时，若其名下「待使用」邀请码已达上限，会被拒绝；「我的邀请码」页头部显示「待使用 X / N」，达上限时生成按钮自动禁用。管理员可在「设置 → 功能开关」调整该上限。
- **注册地址改为省市联动下拉**：注册页（含登录页注册与注册弹窗）的「联系地址」从纯文本输入框改为**中国省 / 市 / 区三级联动下拉**，选齐地区后下方再填**详细地址**（街道门牌，选填）。数据来自 `@vant/area-data`（民政部标准编码），最终以拼接字符串存储（如「广东省深圳市南山区科技园路 1 号」），与原有自由文本地址完全兼容，无需迁移。选择过程做了性能优化（地址改用 ref），不再因每次选择触发整张表单重渲染而卡顿。
- **手机号 / 公司描述中性化**：注册表单手机号、公司输入框的提示文案去掉了「用于询价对接」「提交询价时自动带入」等用途说明，改为中性描述（如「请输入手机号或座机（选填）」「请输入公司名称（选填）」）。
- **邀请码入口即时生效**：管理员在「用户管理」给当前登录的自己勾选「可生成邀请码」并保存后，TopNav 的「我的邀请码」入口立即出现，无需重新登录。
- **「我的邀请码」菜单图标**：补上了之前缺失的图标（礼品卡样式）。
- **后台菜单新增项自动可见**：修正了「老站点在后台保存过导航后，新增的管理页（如本次的「邀请管理」）不显示或被挤到末尾」的问题——现在以默认导航顺序为骨架合并，新功能项会出现在设计位置；「邀请管理」已改名为 4 字「邀请管理」并放在「系统设置」上方，与其它 4 字菜单对齐。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## 部署备注

本次改动**不涉及数据库迁移**，是镜像内的代码与前端资源变更（仅前端新增依赖 `@vant/area-data`，已随 web 镜像打包）。默认跟随 latest 的部署由 Watchtower 自动更新；需要立即更新时执行：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.5.2 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health
curl -s http://localhost:3780/api/settings/version   # 应显示 v3.5.2
```

升级后：管理员后台会出现「邀请管理」菜单（位于「系统设置」上方）；「设置 → 功能开关」可调「邀请码待使用上限」；注册页地址变为省市联动下拉 + 详细地址。
