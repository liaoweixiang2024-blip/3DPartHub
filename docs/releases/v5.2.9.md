## 标签描述

v5.2.9 rebuilds login brute-force protection so strangers can no longer lock out an account they only know the email of, and fixes several mobile layout issues. Login protection now works in four layers: 5 failed attempts on one email escalate to a graphic captcha (the legit owner can still sign in by solving it - the account is NOT locked); 30 failures with captcha (sign of captcha being broken) triggers a hard temporary lock; 20 failures from one IP locks that network for 15 minutes; a global rate limiter caps login requests per IP. Admins get a one-click "unlock login" button (key icon) in user management that clears both the account lock and captcha state instantly - no waiting 15 minutes. On mobile, the selection page category list no longer flashes a stuck "selected" highlight while scrolling (iOS keeps :hover/:active on the touched card for the whole drag - those styles and the press animation are removed for mobile; tap still shows a selection highlight before navigating). The profile page header is now fixed like other pages with internal scrolling, the category-nav page gets the same 16px top spacing as every other mobile page, and the change-email / change-password dialogs are visually unified and no longer covered by the bottom nav bar (they stop above it and it stays tappable). Session-expiry redirects to /login no longer pop a spurious top-right error toast. No database migrations.

## 登录防爆破四层防护

### 问题

- 原逻辑按邮箱计数失败即锁定账号：陌生人只要知道用户邮箱，故意连输错密码就能**把别人的账号锁死**（恶意锁号）
- 无图形验证码，密码可被脚本持续爆破

### 方案（四层递进）

| 层         | 触发条件                                       | 效果                                                       | 解除                         |
| ---------- | ---------------------------------------------- | ---------------------------------------------------------- | ---------------------------- |
| 图形验证码 | 同一邮箱失败 5 次                              | 登录表单出现验证码，**输对仍可正常登录**（真用户不被锁死） | 15 分钟无失败自动消失        |
| 保底硬锁   | 带验证码仍持续失败到 30 次（验证码被破解迹象） | 账号临时锁定，防爆破                                       | 15 分钟自动 / 管理端立即解锁 |
| IP 硬锁    | 同 IP 失败 20 次                               | 锁攻击者网络，受害者不受影响                               | 15 分钟自动 / 管理端解锁     |
| 请求限流   | 每 IP 每 15 分钟 50 次登录请求                 | 最外层兜底（原有）                                         | 自动                         |

- **管理端解锁**：用户管理页每行新增🔑按钮，一键清除该账号登录锁定+验证码状态，返回被锁用户邮箱
- 验证码复用注册已有的 svg-captcha 体系（单次使用、Redis 存储）

### 验证

- 全路径 API 实测：失败 1-4 次正常报错 → 第 5 次 `captchaRequired:true` 透传前端 → 缺验证码 `CAPTCHA_REQUIRED` → 正确验证码+正确密码**登录成功**（真用户不被恶意锁死）→ 计数 30 返回 `ACCOUNT_LOCKED` → 管理端解锁后立即恢复登录 → 未认证调解锁 401
- Playwright 浏览器 E2E：5 次失败后验证码图自动出现 → 填对 → 登录成功跳首页

### 记住登录排查结论（附带说明）

- 机制实测无漏洞：登录后重启服务（模拟系统更新）、清空 Redis 登录态均存活；refresh token 30 天滑动续期
- 生产若出现「更新后全员需重新登录」，检查 `/opt/3dparthub/.env` 的 `JWT_SECRET` 是否在更新时被改动过——**该值任何情况下都不能变**

## 移动端修复

### 选型页分类卡滑动粘色

- **问题**：iPhone 滑动分类列表时，手指落点那张卡全程显示「被选中」样式（深灰底+阴影抬起）
- **根因**：iOS WebKit 触摸滚动时 `:hover`/`:active` 会全程粘在落点卡片上不释放（Chromium 会释放）
- **修复**：移动端分类卡移除 hover/active 视觉样式与按下动画（按下即现的动画在滑动手势「先按下再拖动」下也会闪现）；真实点击仍有选中高亮（橙色左条+对勾）再进入分类
- **验证**：触摸模拟三场景全过——按住 400ms 全程无反馈 / 「按下→立刻拖动」刚过滚动阈值即干净 / 真实点击正常进分组

### 其他移动端修复

- **个人设置页**：标题固定（与其他管理页一致），内容区内部滚动，不再整页滚动导致标题跟着走
- **系统选型导航页**：移动端标题区块补 16px 顶部间距（与其他页面统一）
- **换绑邮箱/修改密码弹窗**：样式统一（同款头部/错误容器/遮罩），弹窗停在底部菜单栏上方不再被遮挡，菜单栏保持可见可点
- **登录过期**：跳转登录页不再同时弹右上角错误提示（跳转本身已说明问题）
