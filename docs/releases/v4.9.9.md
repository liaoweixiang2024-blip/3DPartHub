## 更新标题

3DPartHub v4.9.9 - 下载统计重构：新增下载事件表，分享/匿名/批量下载全量打点 + 下载趋势图修复

## 标签描述

v4.9.9 rebuilds the download statistics pipeline around a new append-only events table. A new `download_events` table now records one row per real download with userId nullable and a source tag (model / share / batch), and every download path writes to it: detail-page direct downloads (both the synchronous recorder and the Redis-backed async queue), share-link downloads (previously invisible to admin stats — they only bumped the share counter), batch ZIP packaging, and favorites-page downloads. Existing `downloads` history rows were backfilled into the events table by the migration, and the table remains untouched as the data source for the "My Downloads" page and daily download limits. The admin dashboard (today / 7-day / active downloaders / bytes / format distribution / 14-day trend chart / recent downloads / paginated records) switched from the deduplicated user-history table to the events table, so anonymous and share downloads finally appear; share downloads also increment the model's public download count, and record rows attribute share downloads to their creator ("admin 的分享") with the share icon fixed to a name that actually renders. Two pre-existing trend-chart bugs were fixed: daily buckets were keyed by UTC date so events after 8am local time fell outside the last bucket and were dropped, and a collapsed-flex CSS bug (items-end shrinking column heights to content, making every bar exactly 0px — the chart had never drawn a single bar since launch, masked until now by the missing data) — Playwright-verified bars now render at full height. Database migration included: additive-only new table + backfill, no existing data is modified; it runs automatically on `docker-compose up -d`.

## 更新描述

本次为 **下载统计体系重构**：管理端「下载统计」从只看「登录用户去重历史」升级为「全量下载事件流水」，分享链接、匿名、批量打包下载全部入统计，并修复下载趋势图从上线起就画不出柱子的两个 bug。**含数据库迁移**（纯新增表 + 历史回填，不动现有数据），服务器 `docker-compose up -d` 时自动执行。

**① 新增下载事件表（download_events）**

- 每次真实下载记一行：`user_id` 可空（匿名可记）、`source` 标记来源（model 详情页 / share 分享 / batch 批量打包）、`share_id` 记分享归因（纯字符串，分享删除后事件保留）
- 迁移自动从 `downloads` 历史表回填存量记录，历史趋势不空白
- `downloads` 历史表原样保留：仍服务「我的下载」页与每日限额计数，双轨互不影响

**② 全下载路径打点（原来只覆盖登录用户直下）**

- 详情页直下：同步落库路径 + Redis 队列批量落库路径都补事件
- **分享链接下载**：原来只加分享自身计数、完全不入管理端统计，现在入事件 + 同步计入模型下载次数
- 批量打包（ZIP）逐模型打点；收藏页下载走统一 recorder 自动覆盖
- noRecord 内部重下不产生事件（不打脏统计）

**③ 管理端统计口径切换 + 分享归因**

- 今日下载 / 近 7 天 / 活跃下载人数 / 文件体积 / 格式分布 / 趋势图 / 最近下载 / 记录分页搜索，全部改读事件表（未登录显示「未登录用户」）
- 下载记录行显示分享归因：「admin 的分享」（分享创建者，删除后显示「分享链接下载」），并简化了原来三段重复的文案；修复分享图标不渲染的问题（图标名不在映射表）
- 「累计下载」仍为模型计数总和，但现在分享下载也会让模型下载次数增长

**④ 下载趋势图两个预存在 bug 修复**

- 时区 bug：按 UTC 日期分桶而日界是本地午夜 → 本地早上 8 点后的下载全部越过最后一个桶被丢弃，改为本地日期分桶
- CSS 塌陷 bug：flex 容器 `items-end` 把列高收缩成内容高 → 柱子百分比高度恒为 0px（**该图从上线起一根柱子都没画过**，此前被"没数据"掩盖），重排列布局后柱子正常按比例渲染
