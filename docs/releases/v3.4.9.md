## 更新标题

3DPartHub v3.4.9 - 修复收藏功能失效（刷新后收藏/取消收藏报错）

## 标签描述

3DPartHub v3.4.9 patch release. Fixes a bug where the favorites (收藏) feature stopped working after a page reload: the zustand store persisted the transient `_pendingIds` Set, but `JSON.stringify(new Set())` produces `"{}"`, so on reload `_pendingIds` was loaded as a plain object and `_pendingIds.has(...)` threw "not a function". This broke the very first line of every favorite / unfavorite toggle on the home list and the model detail page, surfacing as "收藏失败，请重试" (and `t(...)._pendingIds.has is not a function` in the console). Fix: the store's persist layer now only persists `favoriteIds` (via `partialize`) and always reconstructs `_pendingIds` as a fresh Set on load, discarding any stale value left by older versions. Frontend-only fix; no backend change, no DB migration.

## 更新描述

- **修复收藏功能失效**：此前的版本中，用户在首页模型卡片或模型详情页点击收藏 / 取消收藏时，会提示「收藏失败，请重试」，模型详情页还会在控制台报 `_pendingIds.has is not a function`。根因是前端收藏状态（`useFavoriteStore`）写入 localStorage 时，把瞬态的「防并发」字段 `_pendingIds`（一个 `Set`）也一并持久化了，而 `JSON.stringify(Set)` 会变成 `"{}"`；刷新页面读回后 `_pendingIds` 不再是 `Set`，调用 `.has()` 直接抛错，导致整个收藏 / 取消收藏流程在第一步就失败。本次修复：持久化时只保存真正的收藏列表 `favoriteIds`（不再持久化瞬态的 `_pendingIds`），读回时 `_pendingIds` 一律重建为全新的 `Set`，并兼容旧版本可能已写入的脏数据。修复后收藏 / 取消收藏恢复正常，收藏列表数据本身并未丢失或损坏，已有用户的浏览器在下次加载时自动修复，无需手动清缓存。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## 部署备注

本次改动**不涉及数据库迁移 / docker-compose**，是**纯前端修复**（只需更新 web 镜像；api 镜像跟随发版一并打 v3.4.9 标签，内容与 v3.4.8 一致）。默认跟随 latest 的部署由 Watchtower 自动更新；需要立即更新时执行：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v3.4.9 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health
curl -s http://localhost:3780/api/settings/version   # 应显示 v3.4.9
```

注意：少数用户的浏览器若缓存了**旧版本的自建 bundle**（历史上有把后端绝对 IP 烤进 JS 的情况），可能在收藏之外还遇到 CSP `connect-src 'self'` 报错；这类情况清一次站点数据（含旧 Service Worker）再硬刷新即可，服务端镜像已始终提供正确的相对 `/api` bundle。
