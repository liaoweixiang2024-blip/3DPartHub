## 更新标题

3DPartHub v3.4.6 - Redis / 缓存韧性加固

## 标签描述

3DPartHub v3.4.6 patch release — Redis/cache resilience hardening. (1) Cache layer (cache.ts): a single transient command failure (command timeout, OOM write, or JSON parse error) used to flip the global `available` flag and darken the entire cache layer — every subsequent cacheGet returned null and every cacheSet was skipped until the connection re-emitted `ready` or a cacheGetOrSet path re-pinged. The per-command `markUnavailable()` calls in cacheGet/cacheSet/cacheDel/cacheDelByPrefix/cacheGetOrSet are removed; connection availability is now driven solely by the authoritative ready/error/close events, so one bad command no longer takes the whole cache offline. (2) docker-compose Redis: switch maxmemory-policy from `noeviction` to `volatile-lru` (under memory pressure Redis now evicts only TTL cache keys and never BullMQ job keys, instead of rejecting writes and disabling the cache), and raise the default container mem_limit from 128M to 256M so maxmemory plus AOF/BGSAVE fork always have headroom — the container can no longer be OOM-killed before maxmemory kicks in.

## 更新描述

- 缓存层加固：修复一处"单次失败连累整层"的过激逻辑。此前任何一条缓存命令瞬时失败（命令超时、内存写满报错、JSON 解析出错）都会把整层缓存标记为不可用，导致之后所有缓存读取直接返回空、写入直接跳过，直到连接重连。现在连接健康只由 ready/error/close 事件权威决定，单条命令失败只影响那一条（返回空 / 跳过写入），缓存层整体不受影响，下一次请求照常命中。
- Redis 配置加固：① maxmemory 策略从 `noeviction` 改为 `volatile-lru`——内存吃紧时只淘汰带 TTL 的缓存 key（分类 / 设置 / 模型列表等），绝不淘汰 BullMQ 任务 key（避免丢任务），也不再因写失败把缓存层关掉；② 容器内存上限默认 128M → 256M，给 maxmemory + AOF/BGSAVE fork 留足头部，防止数据涨上来时容器先于 maxmemory 被系统 OOM-kill。
- 前端「检查更新」会读取本更新描述（GitHub Release 内容），展示最新版本号与更新内容。

## 部署备注（Redis 配置改动需额外一步）

本次 docker-compose 的 Redis 改动（`volatile-lru` + `mem_limit 256M`）不在镜像里，需在服务器同步 compose 文件后重建 redis 容器才生效。`docker-compose up -d --force-recreate` 会同时重建 api（拉新镜像）和 redis（应用新启动参数）。部署前请确认 `/opt/3dparthub/.env` 里 `REDIS_MEMORY_LIMIT ≥ 2 × REDIS_MAXMEMORY`（实测内存仅 ~2MB，`REDIS_MAXMEMORY=96mb` + `REDIS_MEMORY_LIMIT=256M` 已是 2.6 倍冗余，完全够用）。

```bash
# 默认部署跟随 latest，并由 Watchtower 自动更新 api/web 镜像。
# 需要立即更新时执行：
cd /opt/3dparthub
git pull                          # 同步最新 docker-compose.yml（Redis 配置改动）
docker-compose pull               # 拉取 v3.4.6 api 镜像
docker-compose up -d --force-recreate   # 同时重建 api + redis；保留数据卷，绝不用 down -v
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

# 快速健康检查
curl http://localhost:3780/api/health

# 验证 Redis 策略已生效（应为 volatile-lru）
PW=$(grep '^REDIS_PASSWORD=' .env | cut -d= -f2-)
docker-compose exec -T redis redis-cli -a "$PW" --no-auth-warning CONFIG GET maxmemory-policy

# 只读部署自检并生成报告
curl -fsSL -O https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/scripts/deploy-health-check.sh
sh deploy-health-check.sh --report deploy-health-report.txt --json deploy-health-report.json
```
