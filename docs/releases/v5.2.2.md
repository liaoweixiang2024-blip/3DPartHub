发布日期：2026-09-28

## 更新标题

3DPartHub v5.2.2 - 选型结果模型匹配修复（含 / 型号）+ 选项图片粘贴上传修复（悬停即目标）

## 标签描述

v5.2.2 fixes two selection bugs. Model matching: selection results whose model number contains "/" (e.g. SLF-3/8) never matched the model library where file-name sanitization turns "/" into "_" (不锈钢内牙弯头\_SLF-3_8) — the tail-segment index now takes everything after the first "_" as the model segment (keeping the last segment too for legacy "A_B_C" names), and the match-index cache key was bumped to force a rebuild. Option image paste: a container-level onPaste on the option-settings modal raced the document-level paste router and funneled pasted images into a write-only "**pasting**" sink — toast said success but no image appeared and no upload spinner showed until the user clicked inside the dialog first. The black-hole handler is gone; paste works the moment the value dialog opens regardless of focus, and grid cards are now hover-paste targets themselves (hover a card, Cmd+V, done). No database migrations.

## 选型结果模型匹配修复（含 `/` 的型号）

### 问题

选型结果的型号里含 `/` 时（如 `SLF-3/8 不锈钢内牙弯头`）匹配不到模型库里的同名模型——模型文件名清洗会把 `/` 变成 `_`（`不锈钢内牙弯头_SLF-3_8`），而匹配索引的型号尾段按全部 `_` 切分，把 `SLF-3_8` 切碎成了 `8`，永远对不上。

### 修复

- 型号尾段提取改为「第一个 `_` 之后的整段」：`不锈钢内牙弯头_SLF-3_8` 的尾段就是完整的 `SLF-3_8`，与归一化后的选型型号（`/` 同样归一为 `_`）精确命中
- 同时保留「最后一个 `_` 段」作为独立索引键，兼容历史「A_B_C 只以 C 为型号」的命名
- 匹配索引缓存键 v3 → v4，升级后强制重建索引
- 全量 19378 个模型验证：SLF/STF/SLN/STN 系列（内牙/外牙弯头、三通等）全部精确命中，异径款与 45° 变体款匹配正确，无错配

## 选项图片粘贴上传修复

### 问题（黑洞 handler 抢事件）

首次打开「选项设置」后直接悬停选项图片粘贴：toast 提示「图片已上传」，但**图片不显示、也没有上传中的转圈图标**，必须先点一下选项图片才能正常粘贴上传。

根因是双 paste 处理器抢事件：选项设置弹窗容器上挂了一个容器级 `onPaste`，把粘贴的图片上传到伪选项值 `__pasting__`——这个键全站没有任何界面读取（纯黑洞）。当焦点还留在弹窗内（点过字段选择器/搜索框/卡片），粘贴事件先被容器级 handler 截走：上传进了黑洞、上传状态标记也落在黑洞键上，所以「提示成功但不显示图片、没有上传图标」；真正按悬停分流的监听看到事件已被处理直接放弃。点一下弹窗内区域会把焦点移回 body，事件不再经过弹窗容器，粘贴才恢复正常——这就是「点一下才能用」的原因。

### 修复

- **删除黑洞 handler**：粘贴统一走 document 级分流监听，不再依赖焦点位置——单选项弹窗一打开就能正常粘贴，无需先点一下
- **网格卡片也是粘贴目标**：不点开弹窗，鼠标悬停在哪张选项图片上，Cmd+V 就直接传那个选项值（卡片上有上传转圈反馈）
- 卡片底部提示文字更新为「点击或粘贴上传 / 点击或粘贴更换」
- 顺带修复：以前焦点在弹窗内时，往搜索框粘贴网址文字会被劫持去下载图片（也进黑洞），现在搜索框正常收文字
