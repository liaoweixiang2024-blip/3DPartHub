# v5.2.7

发布日期：2026-09-30

## 更新标题

3DPartHub v5.2.7 - 修复转换稳定性重构（失败不再打坏模型/卡死可重试/gmsh 面网格化）+ API 缓存假象修复 + 选型结果画册默认折叠

## 标签描述

v5.2.7 hardens the model "repair re-conversion" (reconvert-gmsh) pipeline for stability and fixes a stale-cache illusion. First, a failed repair conversion no longer bricks the model: previously the model status was flipped to FAILED before the conversion subprocess ran, so any failure left a previously-usable COMPLETED model unopenable ("该模型转换失败，暂无预览") — now the original status and preview are automatically restored on failure (with a cache-busting version suffix on the GLB URL). Second, models stuck in PROCESSING (e.g. after a crashed worker) blocked retries with a permanent 409; after a 20-minute staleness window the guard now lets a new attempt through. Third, the gmsh fallback switches from volume meshing (-3, which failed wholesale on many STEP files and lost output on non-zero exit) to surface meshing (-2) with output-driven success detection, higher mesh density (curvature refinement 20→30, finer size ladder, smaller min edge), OCCT fragment hole-patching as a fallback, and an opt-in exact-surface-patch mechanism (per-model JSON under static/surface-patches, welded index-level into the mesh with globally recomputed smooth normals). Fourth, GET /api responses now send Cache-Control: no-cache — previously browsers heuristically cached API responses, so a normal refresh could show a stale model preview even after re-conversion. Fifth, the admin edit dialog surfaces the real error message when regeneration fails. Finally, selection result cards no longer auto-expand the catalog (画册) — it starts collapsed behind the existing "查看画册" toggle. No database migrations.

## 更新描述

本次为 **修复转换稳定性 + 缓存修复 + 画册默认折叠** 版本，无数据库迁移，需同时更新两端镜像。

## 修复转换稳定性重构

### 问题

- **失败反杀模型**：修复转换失败后，原本能正常预览的模型直接变成「该模型转换失败，暂无预览」，详情页打不开
- **卡死无解**：模型卡在「转换中」状态时，重新发起修复转换永远返回 409，只能等或手动改库
- **gmsh 体网格全盘失败**：`-3` 体网格化对部分 STEP 文件整单失败，且非零退出码时连已生成的产物也被丢弃
- **报错无信息**：管理端「从模型重新生成」失败只弹「重新生成失败」，无法定位原因

### 修复

- **失败自动恢复**：修复转换失败时自动恢复模型原有状态与预览地址（原 COMPLETED 模型保持可用），预览 URL 带版本号打散缓存
- **卡死放行**：PROCESSING 状态超过 20 分钟视为陈旧，允许重新发起修复转换
- **gmsh 面网格化**：`-3`→`-2` 面网格 + 产物驱动判定（有产物即成功，不再只看退出码）；曲率网格细化 20→30、尺寸阶梯更细、最小边长收紧，网格密度与光滑度显著提升
- **补洞兜底**：OCCT 碎片补洞作为无精确补丁时的兜底；新增按模型 opt-in 的精确曲面补丁机制（`static/surface-patches/<modelId>.json`，索引级焊接进主网格并整体重算平滑法线）
- **真实报错**：重新生成失败时前端显示服务端真实原因（如「转换子进程异常退出」「gmsh 转换失败」）

## API 缓存假象修复

### 问题

浏览器对 GET `/api` 响应做启发式缓存——修复转换完成后普通刷新页面，全程零网络请求，看到的仍是旧模型，误以为「修复没生效」。

### 修复

`GET /api/*` 响应统一加 `Cache-Control: no-cache`（静态资源保持原缓存策略），配合重转后预览 URL 的版本号参数，刷新必拿最新状态。

## 选型结果画册默认折叠

- 选型结果卡片中的画册（图片/PDF）默认**不再自动展开**，点「查看画册」按钮展开、再点折叠——结果列表更紧凑，画册内容不抢占首屏

## 升级说明

- 无数据库迁移（schema 未变更）
- 服务器更新：`docker-compose pull && docker-compose up -d`，浏览器强刷（Cmd+Shift+R）；验证：①选型出结果后画册默认折叠，点「查看画册」可展开；②管理端对一个模型点「从模型重新生成」，若失败模型详情页应仍可正常打开且保留原预览
