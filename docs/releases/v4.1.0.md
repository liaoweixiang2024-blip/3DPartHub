## 更新标题

3DPartHub v4.1.0 - 模型分类访问权限：分类级「公开/受限」+ 角色/指定用户白名单

## 标签描述

3DPartHub v4.1.0 introduces category-level access control for the model library. Each category can now be marked "restricted" with a whitelist of allowed roles (Editor/Viewer/Internal) and/or specific users — anyone matching either can see it, everyone else (including anonymous visitors) cannot. Restrictions propagate down the subtree: child categories and their models inherit the parent's restriction even if individually public. ADMIN always sees everything. Enforcement covers every read path: category tree & flat list (upload/edit pickers included), model list, search, model counts, model detail (including grouped variant siblings), downloads (even with login-free downloads enabled), drawing PDFs, version lists, model compare, favorites list & batch download, download history & batch archive, and download-token issuance. Cache keys are bucketed per visibility so restricted and public users never share cached lists; changing a category's access flushes model/favorite caches. Public share links (/s/xxx) are intentionally NOT affected. Includes a DB migration (categories gain restricted/allowed_roles/allowed_user_ids columns — no data backfill, all categories default to public). Admin UI: category modal gains an access-control section (switch + role chips + user search multi-select), category list shows a "受限" badge, and the switch control is unified with the settings page via a new shared AppSwitch component.

## 更新描述

本次为**新功能**：模型分类级访问控制——「某些分类只给内部员工或指定客户看」。

**⚠️ 有数据库迁移**：categories 表新增 restricted / allowed_roles / allowed_user_ids 三列（无数据回填，所有分类默认公开，升级后行为不变）。

**功能说明**

- 后台「分类管理」编辑弹窗新增**访问限制**区块：
  - 开关：公开（默认）↔ 受限
  - 受限时配置白名单：勾选角色（编辑者/访客/内部）和/或搜索添加指定用户，**满足其一即可见**
  - 白名单为空时弹窗拦截保存（除管理员外谁都看不到，防误操作）
- 受限语义：该分类**及其全部子孙分类**下的模型，对非白名单用户（含匿名访客）完全不可见——列表、分类树、搜索、总数统计、收藏、下载历史、详情直连、下载、图纸、版本、模型对比、批量打包全部拦截（403/不出现）
- **管理员始终可见一切**；上传/改分类的下拉框里，非白名单用户也选不到受限分类
- 权限修改**即时生效**（无需重新登录，每请求实时查询）
- 已有收藏/下载记录里的模型被设为受限后自动从对应列表消失

**明确不受影响**：公开分享链接（/s/xxx）保持任何人可打开（按用户选择，分享出去的链接不因分类受限而失效）。

**性能**：分类表极小（几十行），权限判定为每请求一次轻量内存计算；Redis 缓存按「可见性桶」分 key——无受限分类/管理员/匿名用户沿用原缓存 key（命中率不变），受限用户命中各自的桶；修改分类权限会清空模型/收藏相关缓存。

**其他**

- 设置页的开关控件提取为共享组件 AppSwitch，分类弹窗复用同一规格（修复两处开关样式不一致）

前端「检查更新」会读取本更新描述展示最新版本号与更新内容。

## 部署备注

本次**有数据库迁移**（容器启动时自动执行 `prisma migrate deploy`，为 categories 加 3 列，无数据变更、可安全回滚镜像）。升级步骤：

```bash
cd /opt/3dparthub
docker-compose pull               # 拉取 v4.1.0 api / web 镜像
docker-compose up -d              # 重建 api / web 容器（保留数据卷，绝不用 down -v）
# 更新后强制刷新浏览器：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

curl -s http://localhost:3780/api/settings/version   # 应显示 v4.1.0
```

升级后注意：

- **默认行为不变**：所有分类初始都是公开，需要在后台手动开启限制
- 建议先用测试分类 + 测试账号验证：受限分类对访客不可见（列表/搜索/直连详情均 403 或消失）、对白名单用户/管理员正常
- 分类权限修改后其他在线用户**最长 10 分钟**内可能看到旧缓存（列表/搜索缓存 TTL）；重新加载页面即可立即刷新
- 公开分享链接不受此功能影响

默认跟随 latest 的部署由 Watchtower 自动更新。
