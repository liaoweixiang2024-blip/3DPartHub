# v5.5.5

发布日期：2026-10-12

## 更新标题

3DPartHub v5.5.5 - 修复生产环境大备份「下载完成后又从头重下」（响应头禁用代理磁盘缓冲 X-Accel-Buffering: no，源码侧生效无需改服务器配置）+ 下载完整性诊断日志

## 更新描述

修复生产环境（经代理转发）下载 6GB+ 备份文件时「浏览器进度走完却不标记成功、同一下载又从头重新开始」的问题。本地直连无此问题，仅部署环境出现。根因在代理层的响应磁盘缓冲：nginx 反代默认对响应做磁盘缓冲（proxy_buffering on，temp file 上限默认 1GiB），GB 级流式响应超限或缓冲异常时上游连接被掐，浏览器收到「提前结束但短于 Content-Length」的响应，Chrome 判定下载失败自动重下。本次通过 nginx 官方的响应级开关（X-Accel-Buffering: no 响应头）让代理对本类响应禁用缓冲直接透传——由服务端代码发出，无需修改任何服务器/代理配置。同时补上响应完整性核对日志，若问题再现可直接从 API 日志定位掐断环节。仅服务端改动，无数据库迁移。

## 修复清单

### 1. 生产环境大文件下载完成后整单重下（核心修复）

- **现象**：生产环境下载 6GB+ 备份，浏览器下载进度走完后不显示成功，同一下载从头重新开始；本地直连无此问题；关闭代理缓存（proxy_cache）无效
- **根因**：下载链路上的 nginx 反代默认对响应做磁盘缓冲（`proxy_buffering on`，临时文件上限 `proxy_max_temp_file_size` 默认 1GiB）。GB 级流式响应超过缓冲上限或缓冲环节异常时，代理掐断到上游的连接，把已缓冲数据发给浏览器——浏览器端表现为收到「提前正常结束但字节数短于 Content-Length」的响应，Chrome 判定下载被中断并自动重下。proxy_cache（缓存）与 proxy_buffering（缓冲）是两个独立机制，关闭缓存不影响缓冲
- **修复**：Node 直连流式下发（备份下载路径）的响应头加入 `X-Accel-Buffering: no`——这是 nginx 官方的响应级开关，链路上的代理收到该头即对本响应禁用磁盘缓冲、直接透传，从根上消除缓冲超限掐流；无需修改任何代理配置
- 注：v5.5.4 的下载防重入（防重复点击拉起并行下载）继续生效，但本条修复针对的是单条下载自身的重下

### 2. 下载响应完整性诊断日志

- 响应正常结束（finish）时核对已发送字节与 Content-Length，不一致记录错误日志
- 连接在响应写完前被掐断（close 早于 finish 且字节未发满）时记录告警日志（含期望/已发字节数与 Range 区间）
- 用途：若大文件下载问题在任何环境再现，可直接从 API 日志区分「流被代理中途掐断」与「字节收满仍被浏览器判定失败」两类场景，精确定位故障环节
