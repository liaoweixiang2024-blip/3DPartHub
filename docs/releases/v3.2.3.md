## 更新标题

3DPartHub v3.2.3 - 企业部署与前台体验稳定版

## 标签描述

3DPartHub v3.2.3 production release with adaptive Docker resource tuning, safer low-memory defaults, deployment health-check hardening, refined desktop search behavior, early username validation, public account policy exposure, and refreshed GHCR images.

## 更新描述

- Docker 纯部署资源策略优化：Compose 默认值改为低配安全兜底，手动部署和一键部署会先按服务器总内存自动写入 `.env` 资源档位。
- 新增 2G 低内存档位：API、Web、PostgreSQL、Redis 默认内存、CPU、worker、连接池和 Redis maxmemory 统一收敛，避免小服务器首次部署过载。
- 企业部署自检加强：部署健康检查会复核容器运行时 memory/cpu 限制、资源预算、Redis 鉴权健康检查、备份目录和运行日志，发现超配会阻止上线。
- Docker 面板内存说明完善：文档明确 `已用内存 / 上限` 不代表预占内存，`340MB / 12GB` 表示当前只用了 340MB，12GB 是保护上限。
- 桌面端右上角搜索优化：搜索入口改为弹出式独立草稿，输入内容不会提前串到模型首页搜索框，提交后再同步搜索并跳转。
- 右上角搜索视觉细节优化：搜索面板、输入区域、清空按钮和提交按钮重新调整，和新主题顶部工具栏更协调。
- 注册用户名提前校验：注册弹窗和登录页注册模式会在输入阶段校验用户名长度和字符格式，不再等提交后才提示。
- 公共设置补充账号策略：前台可读取后台配置的用户名最小/最大长度，注册前端和服务端规则保持一致。
- README 和 `.env.example` 补充生产部署说明：区分根目录 `.env` 和本地开发 `server/.env`，补充备份签名/加密密钥和资源调优顺序。
- 发布前验证包含 Compose 配置校验、部署工具回归、Git 空白检查、前端类型检查、Lint、格式检查和生产构建。
- 镜像已同步更新：api/web 均发布 v3.2.3 与 latest 标签。

```bash
# 默认部署跟随 latest，并由 Watchtower 自动更新 api/web 镜像。
# 需要立即更新时执行：
cd /opt/3dparthub
curl -L -o docker-compose.yml https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/docker-compose.yml
touch .env
grep -q '^IMAGE_TAG=' .env && sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=latest/' .env || echo 'IMAGE_TAG=latest' >> .env
curl -fsSL -O https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/scripts/tune-resources.sh
sh tune-resources.sh .env --no-runtime
docker compose pull
docker compose up -d --force-recreate

# 快速健康检查
curl http://localhost:3780/api/health

# 只读部署自检并生成报告
curl -fsSL -O https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/scripts/deploy-health-check.sh
sh deploy-health-check.sh --report deploy-health-report.txt --json deploy-health-report.json

# 采集脱敏证据包用于支持和最终验收
curl -fsSL -O https://raw.githubusercontent.com/liaoweixiang2024-blip/3DPartHub/main/scripts/collect-deploy-evidence.sh
sh collect-deploy-evidence.sh
```

把 `deploy-evidence-*.tar.gz` 和同名 `.sha256` 回传到仓库后可执行：

```bash
npm run deploy:acceptance -- deploy-evidence-YYYYMMDD-HHMMSS.tar.gz
npm run deploy:report:verify -- deploy-evidence-YYYYMMDD-HHMMSS.tar.gz --max-age-hours 24 --summary deploy-health-acceptance.md --summary-json deploy-health-acceptance.json
```
